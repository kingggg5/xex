## Handoffs

1. Each worker validates its own outputs and returns exact paths, checks and unresolved dependencies.
2. The primary reviews those outputs together against the compact-region objective and current art.
3. Live integration proceeds only when renderer geometry and authoritative collision/content refer to the same coordinates. A newly proposed bluff must have a visible, verified asset before its collider is activated.
4. District packages must retain matching distant scenery while near detail loads. Asset failure keeps the previous representation; residency limits must not be presented as measured FPS.
5. Native Babylon camera review and target-device checks determine visual/playable acceptance. Passing data tests, polygon counts, or Blender export alone are insufficient.

## Current limits

- Preserve the metre scale and blueprint town anchors: gate Z24, fountain Z176, castle Z272. Compact connectors do not mean shrinking characters or buildings.
- The live movement path is still planar XZ. Terrace height traversal needs a shared physics/content solution before walkable stairs are claimed.
- GTX 1050 has 2 GiB VRAM and driver 560.94. Pixel Match CPU processing is feasible; the pinned Pixal3D inference prebuilt is not currently eligible. UniMate CPU fit and speed are unverified.
- No worker installs drivers, executes remote installers, downloads model weights, spends provider credits, changes credentials, or edits the canonical city master/runtime packages in this workflow.
- Sunmeadow is first; lava remains subsequent work. Full mobile performance and 500-player capacity are unqualified.
