# วิเคราะห์ Lumivara Online และแนวทางพัฒนา Xexoria

ฉบับรวมผลทดลองเล่น การตรวจ UI คู่มือ และประวัติอัปเดตที่เข้าถึงได้

**วันที่ตัดข้อมูล:** 2 ตุลาคม 2026 · เวลาทดลองใช้ UTC · เวลาแพตช์ใช้เวลาไทย UTC+7

## ข้อสรุปสำหรับตัดสินใจ

Xexoria ควรนำความชัดเจนของเป้าหมาย การจัดการของ ความต่อเนื่องระหว่างหน้าจอ และเงื่อนไขการเล่นร่วมกันจาก Lumivara มาประยุกต์ก่อน การเพิ่มจำนวนระบบให้ใกล้กันยังไม่สำคัญเท่าการทำวงจร 3D ที่เดิน ต่อสู้ หลบ เก็บของ เล่นกับเพื่อน และกลับเข้าเกมแล้วข้อมูลคงถูกต้อง

Lumivara เป็นเกมพิกเซลมุมมองด้านบนที่มีทั้งการเลือกเป้าหมายให้โจมตีต่อเนื่องและ Auto Play หลายเงื่อนไข การศึกษาครั้งนี้จึงมีคุณค่าสูงด้านโครงสร้าง MMO และ UX แต่ไม่ใช้เป็นผลทดสอบว่ากล้อง การฟัน hitbox หรือการหลบแบบ 3D ของ Xexoria ควรทำอย่างไร

**ข้อค้นพบที่เปลี่ยนคำแนะนำอย่างมีนัยสำคัญ**

1. **การปิด Auto Play ไม่ได้แปลว่าโจมตีครั้งเดียวต่อการกดหนึ่งครั้ง** การเลือก Wind Dummy ทำให้เดินเข้าระยะแล้วโจมตีซ้ำ คลิกพื้นจึงหยุดได้ และมีการฆ่า Dew Bunny จริงพร้อม EXP log
2. **เลเวลบนแผนที่ไม่ได้เป็นประตูล็อกทุกกรณี** ตัวละคร Base Lv.3 เดินทางถึง Frostveil Pass และ Sunscar Desert ได้จริง Travel ที่เห็นเป็นการเดินนำทางผ่านพื้นที่เชื่อม ไม่ใช่การวาร์ปทันที
3. **หน้าจอจำนวนมากใช้ข้อมูลชุดเดียวกัน** กฎย่อยของเชื่อมกับ Auto Play, pet ใช้กฎเก็บของ, gear/passive/hotbar ผูกกับอาชีพ และ mail เชื่อมรางวัลกับร้านค้า การทำทีละหน้าจอโดยไม่มีแบบจำลองข้อมูลร่วมจะเสี่ยงต่อของหายและสถานะขัดกัน
4. **Wiki ไม่ใช่สเปกปัจจุบันที่เชื่อได้ทุกบรรทัด** พบข้อความเก่าทั้งภาษาไทยและอังกฤษ โดยเฉพาะพาสซีฟข้ามอาชีพและค่าสเตตัสมอน ต้องตามประวัติการเปลี่ยนกฎก่อนใช้ตัวเลข
5. **ความขัดแย้งด้านนโยบายและต้นทุนต้องแก้ก่อนเปิดเงินจริง** ข้อความ reset Gold, การเปลี่ยนชื่อ และค่าคลังไม่ตรงกันใน UI ที่ตรวจ ยังไม่ควรเลือกข้อความหนึ่งมาอ้างเป็นสิทธิ์ผู้ซื้อ
6. **สิ่งที่เหมาะกับต้นแบบ Xexoria คือระบบเล็กที่อธิบายผลได้** ปุ่มที่ล็อกต้องบอกเหตุผล ของหรือแต้มที่จะหายต้องมี preview คำขอซ้ำต้องไม่ให้ผลซ้ำ และหลัง reconnect ต้องกลับสู่ข้อมูลจริงของ server

รายงานนี้รวมทุกส่วนไว้ในไฟล์เดียว โดยแยกผลที่เกิดขึ้นจริง กติกาที่ UI/เอกสารระบุ การคำนวณตามสมมติฐาน และข้อเสนอใหม่สำหรับ Xexoria ไม่มีการตรวจหรือแก้ repository ของ Xexoria และไม่ได้รับรอง implementation ภายในของ Lumivara

## 1 ขอบเขตและระดับหลักฐาน

### 1.1 ตรวจอะไรจริง

ทดลองผ่าน cloud browser บน [Lumivara Online](https://lumivaraonline.com/) ด้วย Guest ตัวทดสอบใหม่ แล้วตรวจซ้ำกับตัวเดิม รอบแรกเดินตามบทเรียน เปิด Auto Play ช่วงสั้น หยุดระบบ รับรางวัลเควสแรก และลองเพิ่ม/ลดแต้มสกิลใน preview โดยไม่ Apply รอบลึกต่อมาตรวจหน้าจอและ interaction 80 สถานะ เก็บภาพประกอบการตรวจ 53 ภาพ ทั้งนี้จำนวนสถานะหรือภาพไม่เท่ากับจำนวนระบบที่ผ่านการทดสอบปลายทาง

พื้นที่ที่ไปถึงและตรวจสถานะได้มี Aurelia Forum, Verdant Forest, Frostveil Pass, Sunscar Desert และ Training Grounds ตัวละครในรอบลึกเริ่ม Base Lv.3 / Novice Job Lv.1 และขึ้นเป็น Base Lv.4 / Job Lv.2 หลังฆ่า Dew Bunny ช่วงท้าย จากนั้นล้มจาก Rootling และเลือกกลับเมืองได้ ก่อนออกสู่หน้า login โดย Auto Play เป็น OFF

ไม่ได้ซื้อ เติมเงิน ผูก Google เทรด ส่งข้อความ ชวนผู้เล่น เข้ากิล ทำลายของ หรือใช้แต้มถาวรในรอบลึก ไม่ได้ทดสอบมือถือหรือ gamepad จริง ไม่ได้ต่อสู้ Elite, Leader หรือ world boss ที่ยืนยันชนิดได้ ไม่ได้เปิดหน้าระบบ Fusion สำเร็จ ไม่ได้พบหน้า achievement เฉพาะ และไม่ได้เปลี่ยน channel/region

### 1.2 แยกหลักฐานห้าระดับ

| ระดับ | ความหมาย | ตัวอย่างที่ใช้ในรายงาน |
|---|---|---|
| ผลทดลองจริง | มีเหตุการณ์และสถานะก่อน–หลังรองรับ | ฆ่า Dew Bunny มี EXP log; KO แล้วกลับเมืองและ HP/SP ฟื้น |
| UI ปัจจุบัน | เปิดหน้า สลับแท็บ หรืออ่านข้อความจริง | ช่อง passive 4 ใช้งาน 2 ล็อก; ปุ่มซื้อ disabled; ตลาดมี order editor |
| เอกสารระบุ | อ่าน Wiki, FAQ หรือประกาศทางการ | สูตรต่อสู้, โอกาสสุ่ม, กติกา Nocthar และประวัติเปลี่ยนระบบ |

ผล runtime ใช้ยืนยันเฉพาะสิ่งที่วัดในบริบทนั้น UI ใช้ยืนยันหน้าจอและกติกาที่แสดง ส่วนประกาศเฉพาะเรื่องที่ใหม่กว่าใช้แทนกฎเก่าใน Wiki ในระดับเอกสาร ถ้ายังไม่ได้ทดลอง ห้ามเปลี่ยนคำว่า “ประกาศว่า” เป็น “ทำงานจริงแน่นอน” และถ้าสองแหล่งขัดกันโดยยังไม่มีหลักฐานชี้ขาด ให้เก็บข้อขัดแย้งไว้

### 1.3 ขอบเขตเอกสารและประวัติ

เปิด Wiki ทุกหมวดหลัก รวมรายละเอียดมอน/Leader อาวุธ ตัวเลือกระดับสกิล และเปรียบเทียบภาษาไทยกับอังกฤษ ดัชนีที่เห็นแสดงมอนรวม Leader 58 รายการ อุปกรณ์ 29 ไอเทม 95 การ์ด 49 อาชีพ 10 สกิล/พาสซีฟ 64 และพื้นที่ล่า 11 แห่ง จำนวนเหล่านี้เป็นข้อมูลของดัชนีที่อ่าน ไม่ใช่คำรับรองว่าครบคอนเทนต์ล่าสุด เพราะมีเนื้อหาใหม่ใน changelog ที่ยังไม่ปรากฏใน Wiki

ประวัติที่ตรวจครอบคลุม 993 รายการ ตั้งแต่ 22 กันยายนถึง 2 ตุลาคม 2026 โดยอ่านเนื้อหา ไม่ได้อาศัยชื่อหัวข้ออย่างเดียว รายการแรกที่เข้าถึงได้เป็นการเริ่มระบบแจ้งอัปเดตวันที่ 22 กันยายน 13:22 น. ไทย และรายการล่าสุดในชุดตรวจวันที่ 2 ตุลาคม 13:45 น. ไทย ยังพิสูจน์ไม่ได้ว่าเป็นแพตช์แรกตลอดประวัติหรือว่าเกมเริ่มในวันนั้น

เกมประกาศว่าเป็น test server ตัวเลข ราคา กติกา และ UI ในรายงานจึงเป็นภาพ ณ วันตรวจ ตัวนับ FPS, Ping และ Online เป็นค่าที่เกมแสดง ไม่ใช่ผล benchmark, load test หรือ security audit อิสระ ข้อความนโยบายชำระเงินเป็นสิ่งที่พบในหน้าจอ ไม่ใช่คำแนะนำทางกฎหมายหรือการรับรองการคืนเงิน

## 2 วงจรเล่นจริงตั้งแต่เข้าเกมถึงกลับเมือง

### 2.1 เข้าเกมและบทเรียนแรก

Guest เข้าเล่นได้โดยไม่ผูกบัญชี และหน้าเข้าเกมเตือนว่าการเข้าถึงตัวละครผูกกับ browser นี้ การตรวจรอบแรกคลิกพื้นแล้วตำแหน่งบน minimap เปลี่ยนพร้อมกล้องติดตาม เห็นเป้าหมายเริ่มต้นและปุ่มนำทางออกจากเมือง จากนั้นเปิด Auto Play ของเกมช่วงสั้นจนเกิดความคืบหน้า หยุดให้เป็น OFF แล้วรับรางวัลเควสแรกได้ เป้าหมายถัดไปเปลี่ยนเป็นการเก็บของ

หน้าสกิลให้เพิ่ม First Aid เป็นสถานะ pending แล้วลดกลับก่อน Apply ได้จริง แต่ไม่มีการยืนยันเรียนสกิลเพื่อทดสอบการรักษา เหตุการณ์นี้รองรับบทเรียนเรื่อง preview และ cancel เท่านั้น

จุดที่ควรปรับใน Xexoria คือใช้ tracker หลักชุดเดียวให้การเดิน โจมตี หลบ เก็บ ใส่ของ และพบเพื่อนต่อเนื่องกัน ชื่อปุ่มต้องอ่านจาก binding ปัจจุบัน การแสดงคู่มือกลางจอและเควสในเมนูรองคนละชุดอาจทำให้ผู้เล่นต้องเชื่อมเป้าหมายเอง

### 2.2 สำรวจห้าพื้นที่และความหมายของ Travel

ไปถึง Aurelia Forum, Verdant Forest, Frostveil Pass, Sunscar Desert และ Training Grounds โดยตรวจตำแหน่ง/พื้นที่ปัจจุบันประกอบ ช่วง Base Lv.3 เดินทางถึงพื้นที่หิมะที่แนะนำ Lv.25–45 และทะเลทรายที่แนะนำ Lv.50–70 ได้จริง ป้ายเลเวลของสองเส้นทางนี้จึงเป็นคำแนะนำสำหรับตัวละครที่ตรวจ ไม่ใช่ hard gate ที่ขวางการเข้า

Travel ทำให้ตัวละครเดินนำทางผ่านพื้นที่และประตูเชื่อม การเดินทางไป Training Grounds ใช้เวลาประมาณหนึ่งนาทีในครั้งที่สังเกต ไม่ใช่ benchmark และไม่ได้พิสูจน์ราคา การหยุดกลางทาง หรือการเข้าถึงทุกโซน กลไกนี้ไม่ควรถูกอธิบายว่าเป็น instant teleport

### 2.4 มอนภาคสนามและขอบเขตหลักฐานบอส

**เส้นทางที่ทดลอง:** ออกจาก Training Grounds สู่ภาคสนาม → เลือกเป้าหมายใกล้ตัว → Attack → Chat → EXP

หลังการฝึก เลือกมอนลักษณะกระต่ายสีเขียวและกด Attack ขณะ Auto Play OFF เห็น HP เป้าหมาย 92/92 การต่อสู้ช่วงนี้จบด้วยหนึ่ง kill ที่ทำให้ Base Lv.3 → 4 และ Job Lv.1 → 2 ต่อมาเปิดแท็บ EXP แล้วพบข้อความระบุ **Dew Bunny, Base EXP +43 และ Job EXP +21** จึงระบุชนิดมอนจาก log หลังการต่อสู้ ไม่ได้เดาชื่อจากภาพอย่างเดียว

หลังเลเวลขึ้น UI แสดง HP 125/125, SP 28/28 และ potion ยังคง 205 ขวด การเห็น HP เต็มหลังเลเวลขึ้นไม่พิสูจน์ว่าไม่เคยถูกโจมตีระหว่างสู้ และการไม่เห็น potion ลดไม่พิสูจน์กฎ potion ทุกชนิด ไม่สรุปว่ามอนนี้ไม่มี loot หรือมี drop rate เท่าไร เพราะไม่ได้สังเกต drop ที่ยืนยันได้จาก kill นี้

ระหว่างเดินพบกลุ่มรูปลักษณ์มอนต่างกันตามตำแหน่ง เช่น ต้นอ่อน เห็ดหมวกแดง มอธ สิ่งมีชีวิตคล้ายราก และแมลงสีทอง แต่เมื่อไม่มี selected target/log ที่ยืนยัน ไม่ตั้งชื่อชนิดหรือค่า stats ให้จากภาพเพียงอย่างเดียว การตรวจครั้งนี้เป็นตัวอย่างมอนปกติหนึ่ง encounter ไม่ใช่ bestiary ครบพื้นที่

**ระดับศัตรูที่ต้องแยกในการอ่านผล:**

- **มอนปกติ:** Dew Bunny มี kill และ EXP log ที่ตรวจยืนยันในรอบนี้
- **Elite:** มีตัวเลือกและคำอธิบายใน Bot Settings ว่าเป็นรูปแบบของแต่ละ species พร้อมตัวคูณ HP/ความเสียหาย แต่ยังไม่พิสูจน์ encounter Elite จริง
- **Leader:** Bot Settings ระบุ Leader Amber Beetle Lv.25 แยกจากชนิดปกติ ระหว่างสำรวจป่าตอนใต้พบแมลงสีทองตัวหนึ่งใหญ่กว่ารอบข้าง แต่ไม่ได้ยืนยัน label จึงไม่จัดว่าได้พบ Leader แล้ว การเห็นชื่อใน checkbox หรือรูปร่างใหญ่เพียงอย่างเดียวไม่ใช่หลักฐานต่อสู้ Leader
- **World boss:** live update notice ระบุชื่อ Nocthar ว่า staff เรียกมาใน boss-hunt event การเปิด notice นี้ไม่ได้แปลว่า boss กำลังเกิด และยังไม่พบ encounter ให้ต่อสู้ในหลักฐานรอบนี้ รายละเอียดจาก Wiki ต้องอ่านแยกในส่วนคู่มือของรายงาน

**สำหรับ Xexoria:** ชื่อ ชนิด ระดับ HP ธาตุและสถานะ elite/boss ควรปรากฏบน target frame ที่อ่านได้ ศัตรูทั่วไปและ boss ต้องมี telegraph/behavior ที่พิสูจน์ได้จากการเล่น ไม่ใช้เพียง HP สูงหรือ label ต่างกันเป็นตัวแทน encounter design บันทึก kill/EXP/loot ด้วย event ID เดียวกันเพื่อให้ผู้เล่นและฝ่าย support อธิบายได้ว่าได้อะไรจากการต่อสู้ใด

### 2.5 การล้มและกลับเมือง

ระหว่างสำรวจป่าตอนใต้เพื่อดูศัตรูเพิ่มเติม เป้าหมายที่ยืนยันชื่อได้เป็น **Rootling Lv.18** มี HP 362/362 แล้วลดเป็น 308/362 ก่อนตัวละครล้ม หน้าตายแสดง HP ผู้เล่น 0/125 และ Cause of death เป็น **Rootling Attack** พร้อมสองทางเลือกคือ Revive here ราคา 750 Silver ที่ disabled กับ Return to town

เหตุการณ์นี้ยืนยันได้ว่ามีการต่อสู้กับ Rootling, ได้รับ damage จน KO และมี death UI บอกสาเหตุ แต่ไม่มีวิดีโอ/trace ที่เพียงพอจะแยกทุก hit, attack interval, telegraph หรือประเภท AI ของศัตรู ไม่ใช้การตายครั้งนี้สรุป difficulty curve ทั้งพื้นที่ และไม่กล่าวว่า Rootling เป็น Leader หรือ world boss

ขณะเปิดหน้าตายตัวละครถือ 50 Silver และไม่ได้ใช้ตัวเลือก revive ที่เสียเงิน **กด Return to town แล้วตรวจสถานะหลังโหลดเสร็จพบกลับถึงเมืองที่พิกัด 30,23, HP 125/125, SP 28/28, Silver 50, potion 205 และ Auto OFF** จึงยืนยันเส้นทาง KO → กลับเมืองฟื้นได้จริงในครั้งนี้ โดยไม่สรุปว่าไม่มีโทษการตายชนิดอื่นจากค่าที่มองเห็นเพียงบางส่วน

**สำหรับ Xexoria:** death UI ต้องบอกสาเหตุล่าสุด ค่าเสียหาย/โทษที่เกี่ยวข้อง และค่าใช้จ่ายแต่ละทางเลือกอย่างชัดเจน ปิด combat input เมื่อ KO, กัน revive ซ้ำ และเมื่อฟื้นให้ UI/ตำแหน่ง/HP/invulnerability อัปเดตจาก state เดียวกัน ต้องมีทางออกที่ใช้งานได้แม้ไม่มีเงินในเกม

### 2.6 สถานะเมื่อจบการตรวจ

หลังฟื้นกลับเมือง ปิด Auto Play ค้างไว้ที่ OFF แล้วออกผ่าน Back to login จนถึงหน้า login ที่มีปุ่ม “กลับเข้าเกม” ของ Guest และคำเตือนว่าตัวละครอยู่ใน browser นี้ การออกถึงหน้านี้ตรวจยืนยันแล้ว แต่ไม่ได้ลงชื่อเข้าอีกครั้งหรือเปิดอุปกรณ์อื่น จึงไม่ใช้เป็นผลทดสอบ persistence ข้าม session/อุปกรณ์ครบวงจร

## 3 ระบบและเส้นทาง UI ที่เปิดตรวจ

ทุกเส้นทางในส่วนนี้เริ่มจาก [หน้าเกม](https://lumivaraonline.com/) หน้าต่างเกมไม่มี deep link แยกที่ตรวจยืนยัน จึงใช้ลำดับคลิกแทน URL ที่สร้างขึ้นเอง ข้อความ “สำหรับ Xexoria” เป็นคำแนะนำใหม่ ส่วนผลของธุรกรรมที่ไม่ได้ยืนยันจะระบุแยกไว้

### 3.1 Settings และการจัดลำดับหน้าต่าง

**เส้นทาง:** More → Settings → Controls (keyboard / gamepad)

หน้า Settings รวมเสียง, ภาษา UI, ห้อง chat ตามภาษา, การแสดงแท็บ chat, FPS limit, การแสดงผู้เล่นอื่น, Skill effects, HUD scale, ปุ่มสัมผัสและความโปร่งใส, damage numbers, item pickup banners, screen shake และ session diagnostics แผง Controls แยกคอลัมน์ Keyboard กับ Gamepad มีการเดิน, Attack/talk/pick up, Auto Play, Sit/stand, potion, Dash, Lock bot, shortcut 1–9 และทางลัดเปิดหน้าต่างหลัก

UI บอกให้เลือกช่องแล้วกดปุ่มใหม่, Esc ยกเลิก, Backspace ล้าง และ left stick ใช้เดินเสมอ มี dead zone และสวิตช์ gamepad แต่ขณะตรวจขึ้นว่ายังไม่พบ gamepad จึงพิสูจน์ได้เพียงว่ามีหน้าตั้งค่า ไม่ใช่การรองรับ controller ในการเล่นจริง

การเปิด Skills ขณะ Status ยังเปิดอยู่ทำให้พบหลายหน้าต่างใน UI ชุดเดียว และสามารถเปิด Passive Loadout หรือ Lore ต่อจาก Skills ได้ การกด Esc เมื่อเปิด Passive Loadout ปิดเฉพาะหน้าลูกโดย Status/Skills ยังอยู่ แต่ accessibility state ของปุ่มเปิด passive ยังเป็น expanded ใน ภาพสถานะหน้าจอ ถัดมา เป็นข้อสังเกตสถานะ accessibility ที่ควรตรวจเพิ่ม ไม่ใช่หลักฐานว่าหน้าต่างยังมองเห็นอยู่หรือ input handler เสีย

**สำหรับ Xexoria:** ทดสอบ stack ของหน้าต่างโดยเฉพาะ focus, Esc, input เกมหลุดไปด้านหลัง และทางกลับจากหน้าลูก การลด effect หรือซ่อนผู้เล่นต้องไม่ทำให้ telegraph หรือสมาชิกปาร์ตี้ที่จำเป็นหายไป เก็บ action ID ชุดเดียวให้ key binding, tutorial และ tooltip อ้างอิงร่วมกัน

### 3.2 Status สกิล อาชีพ และ passive เป็นความก้าวหน้าคนละชั้น

**เส้นทาง:** Status → ค่าสเตตัส; Skills → First Aid → Lore; Skills → Passive Loadout; Class → Class lore; Equipment → All jobs

Status แสดง STR, AGI, VIT, INT, DEX และ LUK พร้อมปุ่มเพิ่ม และมี ATK, DEF, MATK, MDEF, HIT, FLEE, CRITICAL, ASPD, Max HP/SP แยกเป็นผลคำนวณ ตัวละครที่ตรวจมี 6 Status Points แต่ไม่ได้กดเพิ่ม จึงยังไม่ยืนยันว่าปุ่มนี้มีขั้น preview หรือใช้ทันที

Skill Tree ของ Novice แสดง First Aid 0/10 พร้อม rank ลด/เพิ่ม, Skill Point 1, Reset/Apply และ shortcut 1–9 คำอธิบายที่ rank 1 ระบุฟื้น HP 5%, SP 3, cooldown 6 วินาที และธาตุ Water ตัวเลขนี้เป็นรายละเอียด UI ไม่ใช่ผลทดลองรักษาในรอบสอง

Passive Loadout ระบุว่า passive อาชีพปัจจุบันทำงานอยู่แล้ว ส่วนของอาชีพอื่นต้องใส่ช่อง แต่ละอาชีพจำชุดของตนเอง และ Haggler/Markup เป็นข้อยกเว้นที่ทำงานข้ามอาชีพโดยไม่ใช้ช่อง หน้าปัจจุบันแสดง 0/4, ช่อง Empty ที่ disabled และช่องต่อไปที่ล็อก ไม่มี passive ข้ามอาชีพให้เลือก ปุ่ม Save จึง disabled

Class ระบุว่าเปลี่ยนได้ที่ Job Lv.10 และ Base Level คงเดิม ขณะตรวจ Job Lv.1 จึงเลือกหรือเปลี่ยนไม่ได้ หน้า All jobs ยังแสดง requirement ขั้นสูงที่ลงรายละเอียดเป็นสองสาย: Nekobaku ต้อง Merchant และ Mamushi Job Lv.50; Kensei ต้อง Swordsman และ Thief Job Lv.50 พร้อมเลขปัจจุบันของแต่ละเงื่อนไข

Lore เปิดจากสกิลและเลือกอ่านอาชีพที่ยังไม่ได้เล่นได้ มีรายการสกิลพร้อม Job Level ช่วยให้มองเส้นทางระยะยาว แต่เรื่องเล่าไม่ควรใช้แทนคำอธิบาย combat ที่มีค่าระยะ เวลา เงื่อนไขและข้อยกเว้น ไม่ได้ทดลองความสามารถ Kensei จากการอ่านเรื่องเล่า

**สำหรับ Xexoria:** แยก Base Level, Job Level, แต้มใช้จ่าย และ requirement ให้เห็นชื่อชัด วาง preview ก่อน commit ทุกจุดที่ถาวร เมื่อเปลี่ยนอาชีพหรือ loadout ต้องส่งการเปลี่ยนเป็นรายการเดียวที่ตรวจสิทธิ์ได้ และแสดงสิ่งที่ได้รับ/เสียก่อนยืนยัน ห้ามสรุปว่าการเปิด Lore หรือเห็นปุ่มสกิลเท่ากับได้ทดสอบ build นั้นแล้ว

### 3.3 Equipment กับ Skin แยกพลังออกจากรูปลักษณ์ในหน้าจอ

**เส้นทาง:** Equipment → เลือกช่อง → Select item; Equipment → All jobs; Equipment → Skin

Equipment มีช่องมือ หัวสามตำแหน่ง ลำตัว ผ้าคลุม รองเท้า และเครื่องประดับสองช่อง ช่องว่างมีคำแนะนำให้เลือกของจากกระเป๋า มี Auto equip, Unequip all, All jobs และ Allow gear inspect หน้า All jobs ระบุว่าเมื่อสลับอาชีพ ชุดของอาชีพนั้นจะใส่ตาม แต่ตัวละครไม่มี gear จึงยังไม่ได้พิสูจน์การสลับของจริงหรือผลต่อสเตตัส

แท็บ Skin แสดง Wings และ Outfit พร้อม empty state โดยข้อความระบุว่าเปลี่ยนภาพเท่านั้น ไม่กิน equipment slot และไม่กระทบ stats หน้า Skin ใน Item Mall ขยายกติกาของ outfit ว่าผูกกับอาชีพและกลับมาใช้อีกเมื่อเล่นอาชีพเดิม รายการ pose ที่เห็นในร้านไม่ได้ยืนยัน animation ครบทุกทิศระหว่างเล่นจริง

**สำหรับ Xexoria:** เก็บ appearance กับ combat stats แยกกัน และทำ test ว่าสวม/ถอด cosmetic ไม่เปลี่ยนค่าต่อสู้ การตรวจอุปกรณ์ผู้อื่นควรมีการควบคุมของเจ้าของและกติกาสิทธิ์ที่ใช้จริง

### 3.4 กระเป๋าและกฎป้องกันการย่อยของ

**เส้นทาง:** Bag → หมวด/Search/ตัวกรอง → Dismantle many → Keep if → Add option

กระเป๋ามีหมวด Consumables, Equipment, Misc, Cards, Quest และ Special item รวมทั้งค้นหา, Tier I–V, set, การกรอง/เรียงตาม stat และเรียงตามใหม่สุด ชื่อ จำนวน หรือราคาขาย พร้อม Grid/List view ชุดข้อมูลขณะตรวจมี potion ชนิดเดียว จึงยังไม่ใช้เป็นหลักฐานว่าการจัดเรียงของหลายชนิดถูกต้อง

Dismantle many แบ่งงานเป็นสามขั้นที่อ่านตามลำดับได้:

1. เลือกสิ่งที่จะย่อย เช่น Weapon/Armor, tier, slot และชนิดอาวุธที่จะเก็บ
2. เก็บของที่มีคุณสมบัติสำคัญ เช่น refined, ใส่ card, special option, top roll, สอง random stats, อาวุธที่อาชีพนี้ใช้ได้ และของจากผู้เล่นอื่น รวมถึง set rarity
3. เพิ่มกฎเก็บเมื่อ option มีค่าถึงเกณฑ์ เช่น STR ≥ 1 โดยเลือก stat และค่าขั้นต่ำได้

การกด Add option แสดงแถว selector และช่องค่าขั้นต่ำจริง แต่ตอนนี้มี gear 0 ชิ้น รายการ To dismantle เป็น 0/0, Kept 0 และปุ่มทำงาน disabled จึงยังไม่พิสูจน์การคัดเลือกของ ผลตอบแทน การป้องกันของมีค่า หรือการดำเนินการย่อย

มี “Left hand” ปรากฏซ้ำในรายการ Armour slots ของข้อความ UI ที่เก็บได้ ควรตรวจภาพ/ความหมาย slot เพิ่มก่อนเรียกว่า logic bug อาจเป็นปัญหาป้ายชื่อหรือ representation ของ UI

**สำหรับ Xexoria:** preview ต้องบอกชื่อและจำนวนของทุกชิ้นที่จะหาย ผลที่จะได้ และเหตุผลที่อีกชิ้นถูกเก็บ กฎเดียวกันต้องทำงานตรงกันระหว่าง preview กับการย่อยอัตโนมัติ ของ locked/equipped หรือ item ที่เปลี่ยนเจ้าของหลังเปิด preview ต้องถูกตรวจอีกครั้งที่ server

### 3.5 Auto Play เป็นชุดนโยบายที่เชื่อมหลายระบบ

**เส้นทาง:** Bot → Items to collect → รายการย่อย; Bot → Set the dismantle filter; Bot → Monsters to attack → Auto skills → Auto potion → Bot range → Auto rest

ในรอบนี้สถานะเป็น Stopped และไม่ได้เปิด automation เพื่อพิสูจน์กฎต่อไปนี้ ทั้งหมดเป็นพฤติกรรมที่ UI อธิบาย:

- เก็บของเป็นหมวดและรายชนิด กำหนดจำนวนมากสุดได้ โดยเพดานรวมกระเป๋าผู้เล่นกับ pet bag และค่าว่างหมายถึงไม่จำกัด
- Auto-dismantle ใช้ filter ของ Bag → Dismantle many และอธิบายว่าเว้นของที่กฎให้เก็บ ของจากผู้เล่นอื่น ของสวมอยู่ ของล็อก และของใน pet bag
- ตั้งเพดานน้ำหนักเพื่อหยุดเดินเก็บแต่ยังต่อสู้ได้ มีคำเตือนว่าเมื่อถึง 90% จะโจมตีไม่ได้ ค่า threshold ที่เห็นคือ 80% แต่ยังปิดใช้งาน
- เลือก Loot first หรือ EXP first และเลือกรายมอน มี Attack everything, ตัวเลือก Elite และตอบโต้ตัวที่โจมตีก่อนแม้ไม่ถูกเลือกในรายการ การยกเว้นนี้สำคัญต่อความหมายของ whitelist
- ลำดับ Auto skills ทำได้สูงสุด 12 ขั้น มีสกิลซ้ำได้ เริ่มลำดับใหม่เมื่อเปลี่ยนเป้าหมาย ข้ามขั้นที่ติด cooldown หรือ SP ไม่พอ และมี Skills only/Buff only, delay กับสำรอง SP
- Heal before potions, threshold HP/SP, เลือกชนิดยา, haste potion, coating อาวุธ/เกราะ และกติกาแทนธาตุเดิม
- จำกัดวงหาเป้าหมายจากจุดเริ่ม และ Auto rest แยกเกณฑ์นั่งกับลุก พร้อมเงื่อนไขตอบโต้เมื่อถูกโจมตี

UI ระบุว่าบันทึก preferences อัตโนมัติบนอุปกรณ์นี้ ไม่ได้ทดสอบ persistence ข้าม browser หรือข้ามอุปกรณ์ และการเห็นตัวเลือก First Aid ในรายการไม่ได้ยืนยันว่าใช้ได้ในเมื่อยังไม่เรียน

**สำหรับ Xexoria:** ถ้าจะมี automation ภายหลัง ต้องเขียน decision priority ที่อธิบายได้และแสดงเหตุผลปัจจุบัน เช่น “SP ต่ำ จึงรอ”, “ของหนัก จึงหยุดเก็บ” ระบุข้อยกเว้นของ whitelist ให้ชัด และแยกปุ่มเปิดระบบเสี่ยงจากปุ่มเปิดหน้าตั้งค่า ไม่ควรคัดลอกความซับซ้อนทั้งหมดมาใส่เกม action ก่อนเกิดความต้องการจริง

### 3.6 แผนที่และการเดินทางผ่านพื้นที่ที่เลเวลสูงกว่า

**เส้นทาง:** Map → เลือกภูมิภาค → Travel → เปิด Map อีกครั้งตรวจ You are here; Map → Landmarks/World Info/City

แผนที่แสดง 14 พื้นที่ตามหน้า World Info มีเมือง สนาม PvP สนามฝึก และภูมิภาคที่มีเลเวลแนะนำต่อเนื่องถึง 250–270 แผงรายละเอียดบอกเลเวลกับภูมิประเทศ และปุ่ม Travel เปลี่ยนเป็น disabled “You are here” เมื่ออยู่พื้นที่นั้นอยู่แล้ว หน้า City เลือก Aurelia Forum และแสดง Safe Zone การเปิดหน้านี้อย่างเดียวไม่ใช่การเดินทางกลับเมือง แต่ภายหลังการตรวจได้กด Travel กลับถึง Aurelia Forum ฝั่ง east gate จริงตามบันทึก session

**ผลทดลองที่ยืนยัน:** ภายหลังเลือก Frostveil Pass และเดินทาง จุดปัจจุบันเปลี่ยนจาก Verdant Forest เป็น Frostveil Pass; ภายหลังเดินทางต่อ จุดปัจจุบันเปลี่ยนเป็น Sunscar Desert โดยตัวละครยัง Base Lv.3 และ Auto OFF หลักฐานก่อน–หลังนี้มีน้ำหนักมากกว่าการเห็นปุ่ม Travel ที่กดได้เพียงอย่างเดียว

**ลักษณะการเดินทางที่เห็นจริง:** Travel เป็นการนำทางให้ตัวละครเดินข้ามพื้นที่และผ่านทางเชื่อม ไม่ใช่หลักฐาน instant teleport การไป Training Grounds ในช่วงต่อมาผ่านป่าและประตู ใช้เวลาประมาณหนึ่งนาทีตามการสังเกต ส่วนหิมะและทะเลทรายผ่านทางเชื่อมเมืองด้วย ไม่ได้จับเวลาแบบ benchmark และยังไม่ยืนยันทุกเงื่อนไขเรื่องราคา การถูกขัดจังหวะหรือพื้นที่ที่เข้าถึงได้

**สำหรับ Xexoria:** แยก “แนะนำ”, “จำเป็น” และ “อันตราย” ให้ชัดก่อนย้าย ตรวจว่า zone, minimap, quest marker และปาร์ตี้เปลี่ยนตรงกันหลัง server ยืนยัน ระหว่าง transition ต้องป้องกันการส่ง travel ซ้ำและมีทางกู้กลับหากเชื่อมต่อหลุด

### 3.7 Quest Journal เชื่อมกิจกรรมประจำวันกับการปรับอุปกรณ์และธาตุ

**เส้นทาง:** More → Quests → Daily/Exchange/Done

Daily Hunt ระบุฆ่ามอน 100 ตัวต่อวันเพื่อรับ Refine Stone 3 ชิ้นสำหรับ Blacksmith ทุกชนิดนับได้และรีเซ็ตเวลาเที่ยงคืน ขณะตรวจ 3/100 และยังรับไม่ได้ UI ไม่ได้ให้หลักฐานเพียงพอว่าเที่ยงคืนอ้าง timezone ใด จึงไม่ควรนำเวลาของ browser หรือเซิร์ฟเวอร์มาคาดเดา

Exchange ระบุใช้ monster drops ธาตุเดียวกันรวม 50 ชิ้น แลก coating scroll หนึ่งชิ้น เลือก Weapon หรือ Armor ใช้ของเลเวลต่ำก่อนและไม่ใช้ของล็อก แต่ทุกธาตุเป็น 0/50 จึงยังไม่ได้ทดสอบการหักของหรือมอบ scroll

Done แสดง guide quests 1/10 พร้อมรายการล่าสุดและบอกว่ารางวัลของเควสที่จบอยู่ในกระเป๋าแล้ว ช่วยแยก “เสร็จกิจกรรม” ออกจาก “รับรางวัลแล้ว” แต่ไม่ใช่การทดสอบป้องกัน claim ซ้ำ

**สำหรับ Xexoria:** daily ต้องบอก timezone/เวลาที่เหลืออย่างชัดเจน; exchange ต้อง preview ว่ากิน item instance ใดและเว้นของใด; claim และ exchange ควรเป็นธุรกรรมที่ retry ได้โดยไม่รับซ้ำหรือหักซ้ำ

ระหว่างเข้าถึงบริการมีคำพูด NPC ว่า “zero Silver fee!” แต่หน้าบริการที่เปิดกลับแจ้ง 100 Silver จึงเป็นข้อความค่าบริการที่ไม่ตรงกันจากการสังเกตครั้งนี้ ยังไม่ได้พิสูจน์ว่าระบบหักเงินจริงเท่าไร

จึงบันทึกได้ว่าเปิดหน้าต่างและเห็นข้อจำกัดของบริการ ไม่ใช่ว่า Storage ใช้งานครบแล้ว ไม่กดฝาก ถอนหรือ bulk action และไม่สรุปการคิดค่าบริการจากหน้าต่างเดียวว่าเก็บทุกครั้ง ต่อ session หรือมีข้อยกเว้นอย่างไร

**สำหรับ Xexoria:** ปุ่มฝาก/ถอนต้องแสดงสถานะสิทธิ์และค่าบริการก่อนทำงาน; แยก “ไม่มีของ” จาก “เปิดข้อมูลไม่ได้”; การย้ายของต้องรักษา item instance เดียวและ atomic ทั้งต้นทาง–ปลายทาง รวมถึงกรณีกระเป๋าเต็มหรือหลุดกลางทาง

### 3.15 Blacksmith มีทั้งความคืบหน้าถาวรและวงจรซ่อมของ

**เส้นทาง:** Blacksmith → Select equipment → รายการอุปกรณ์; หน้าเดียวกันมี Repair all gear

เปิด Blacksmith และ selector แล้วขึ้นว่าไม่มีอุปกรณ์ที่ refine ได้ มี Silver 50 และ Refine Stone 0 ปุ่ม Confirm refine/Repair all gear เป็น disabled ดังนั้นยังไม่ได้ลอง success/failure, ซ่อม, หักวัตถุดิบ หรือ Protection Stone

ข้อความในหน้าอธิบายวงจรสองแบบซึ่งต้องแยกกัน:

- **ความทนทาน:** ของที่สวมสึกตามการล่ามอน ของแตกไม่ให้ stats จนซ่อม และอาวุธแตกไม่สามารถโจมตีหรือใช้สกิลโจมตีได้
- **Refinement:** อาวุธเพิ่ม ATK หรือ MATK ตามชนิด; ของป้องกันเพิ่ม DEF/MDEF และบางระดับเพิ่ม HP; ระดับสูงบางช่วงเพิ่ม pierce; ทุกครั้งใช้ Refine Stone แม้ไม่สำเร็จ; ข้อความระบุว่าตั้งแต่ +5 การพลาดทำลายไอเทมกับ card หากไม่เลือก Protection Stone

ใช้คำอธิบายนี้ประกอบ Item Mall → Protection Stone ที่ระบุการเริ่มป้องกันตั้งแต่ +4 → +5 ได้ แต่ยังไม่ได้ทดสอบ transition บนของจริงเพื่อแปลความเสี่ยงทุกระดับให้แน่นอน ข้อความ “All gear is in good condition” ในบัญชีที่ไม่มี gear ไม่ใช่ผลทดสอบ durability

**สำหรับ Xexoria:** ก่อนยืนยันแสดงระดับปัจจุบันกับเป้าหมาย โอกาสสำเร็จ ทรัพยากรที่ใช้ทุกกรณี และของ/card ที่อาจหาย แยก repair ออกจาก refine ให้ชัด สำหรับ vertical slice ควรเริ่มจากการอัปเกรดที่คาดการณ์ผลได้ หากมีอาวุธใช้ไม่ได้เพราะแตกต้องมี reason และทางซ่อมที่ผู้เล่นเข้าถึงได้

### 3.16 Reset แสดงขอบเขตว่าเปลี่ยนเฉพาะอาชีพปัจจุบัน

**เส้นทาง:** Reset Master → Status หรือ Skills

หน้าตรวจแบ่งการคืนแต้มสเตตัสกับสกิลอย่างชัดเจน พร้อมสรุปก่อนทำ: Status ของ Lv.3 กลับทุกค่าเป็น 1 และระบุแต้มคืน 6; Skills ของ Novice Job Lv.1 แสดง learned 0 และคืน 1 Skill Point ปุ่ม Status reset แสดง Free ส่วน skill reset disabled เพราะยังไม่เรียน

ข้อความระบุว่า reset เฉพาะ job ปัจจุบันและคง build/skill ของอาชีพอื่น รวมถึง equipment, class และ level ส่วนค่าธรรมเนียมเพิ่มตามช่วง Base Level ไม่ได้กดยืนยันแม้ปุ่มปัจจุบันจะฟรี จึงยังไม่พิสูจน์การคืนแต้ม ผลข้างเคียง หรือการบันทึกข้าม session

**สำหรับ Xexoria:** review ก่อน reset ต้องบอกสิ่งที่จะเปลี่ยน สิ่งที่คงอยู่ จำนวนแต้มคืน และค่าใช้จ่ายปัจจุบัน เมื่อ server ตอบผลแล้วให้ skill bar/loadout/derived stats เปลี่ยนพร้อมกัน และ reject หากราคาหรืออาชีพเปลี่ยนระหว่างเปิดหน้าต่าง

### 3.17 การต่อกลับที่เกิดขึ้นจริงระหว่างตรวจ

เกิดการหลุดชั่วคราวตามธรรมชาติหนึ่งครั้ง มีข้อความ Offline และ Disconnected/Reconnecting แล้วกลับมาเชื่อมต่อเองภายในรอบตรวจโดยไม่ refresh หรือ login ใหม่ หลังกลับเห็น ping และตัวนับ invulnerability ใน UI

นี่เป็นหลักฐานว่าเส้นทางแสดงสถานะและ auto-reconnect ทำงานได้ในเหตุการณ์ครั้งนั้น แต่ไม่มีการควบคุมสาเหตุ ระยะ network outage หรือ transaction ค้างอยู่ จึงไม่รับรองว่า inventory, quest, combat และธุรกรรมทุกชนิดคงถูกต้องหลังหลุด และไม่ใช้ online counter ช่วงนี้ประเมินความเสถียรหรือความจุ server

**สำหรับ Xexoria:** ทดสอบ disconnect แบบควบคุมทั้งระหว่าง idle, combat, travel, claim และ order; หลัง reconnect ต้องได้ server ภาพสถานะหน้าจอ ล่าสุด เคลียร์ input/animation ค้าง และตรวจคำขอที่ค้างด้วย ID แทนส่งซ้ำโดยเดา

## 4 กลไกเชิงลึกจาก Wiki และประกาศที่ใหม่กว่า

ส่วนนี้อธิบายสิ่งที่ต้องรู้เพื่อออกแบบหรือทดสอบระบบ ไม่ใช่คู่มือรับรองค่าปัจจุบันทุกตัว หากสูตรหรือตัวเลขอ้าง Wiki จะคงป้ายแหล่งนั้นไว้ สูตรไม่มีข้อมูลครบเรื่อง rounding/stacking และบางข้อความถูกเปลี่ยนในแพตช์ จึงต้องอ่านส่วนประวัติและข้อขัดแย้งร่วมกัน

### 4.1 อาชีพและโครงสร้าง build

#### สิ่งที่เอกสารระบุ

ฐานอาชีพมี Novice และอีกเก้าสาย: Swordsman, Mage, Archer, Cleric, Merchant, Thief, Mamushi, Kensei และ Nekobaku รูปแบบการเล่นครอบคลุมประชิด เวท ยิงไกล support เศรษฐกิจ พิษสะสม และการเคลื่อนที่เร็ว อาวุธจำกัดตามสาย; bow/kunai พึ่ง DEX ขณะที่ flask ใช้ MATK และจังหวะ ASPD อาชีพพิเศษสองสายระบุการฝึกสองอาชีพก่อนหน้าถึง Job 50 และค่าปลดล็อกครั้งเดียว

Novice เปลี่ยนอาชีพเมื่อ Job 10; Wiki ระบุว่าแต่ละอาชีพเก็บ Job level สเตตัส สกิล และชุดอุปกรณ์ของตนไว้ การกลับมาเล่นจึงเป็นการต่อยอดตัวเดิม [อาชีพ](https://lumivaraonline.com/wiki/#jobs), [ระบบเริ่มเล่น](https://lumivaraonline.com/wiki/#mechanics)

**ข้อแก้ไขปัจจุบัน:** พาสซีฟของอาชีพที่กำลังเล่นทำงานเอง แต่ข้ามสายต้องเลือกใส่ช่อง ไม่ใช่รวมทุกสายไม่จำกัด; Haggler/Markup มีข้อยกเว้นทำงานทั่วทุกอาชีพตามประกาศถัดมา ส่วน 4 ช่องใช้งานได้รับการ ยืนยันประกอบ จากหน้าจอจริงแล้ว [อัปเดต](https://lumivaraonline.com/changelog/#2026-09-30-passive-loadout)

#### สิ่งที่ควรนำไปคิดสำหรับ Xexoria

- ออกแบบแยก `character progression`, `job progression`, `loadout` ตั้งแต่ต้น เพื่อไม่ให้การเปลี่ยนอาชีพทำของหรือแต้มสูญหาย
- ให้การฝึกสายรองสร้างตัวเลือก build มากกว่าบังคับให้ทุกคนเก็บครบทุกสายก่อนเริ่ม endgame
- ใส่ข้อจำกัดพาสซีฟตาม cost budget หรือช่อง loadout; จำนวนช่องเป็นตัวบาลานซ์สำคัญเทียบเท่าค่าดาเมจ
- Preview ก่อนบันทึกควรแสดงพาสซีฟที่เปิดจริง เงื่อนไขอาวุธที่ยังไม่ผ่าน และค่าที่หายไปเมื่อสลับอาชีพ
- อย่านำชื่ออาชีพเฉพาะ ธีมตัวละคร ภาพ หรือสูตรของเกมอ้างอิงมาใช้ตรง ๆ ให้กำหนดบทบาทของ Xexoria เอง

### 4.2 สกิลและสูตรต่อสู้

#### สูตรที่อ่านพบใน Wiki

- โอกาสโจมตีโดน: `clamp(1 + (HIT − FLEE) × 0.0025, 0.5, 1)`
- ค่าลดดาเมจจากเกราะ: `min(255, DEF หรือ MDEF) / 300` แยกกายภาพกับเวท
- หลังเจาะเกราะ: `rawDamage × (1 − max(0, reduction − pierce))` โดยใช้หน่วยสัดส่วนให้ตรงกัน
- Critical ข้ามการเช็กหลบ แต่ยังผ่าน DEF/MDEF; spell critical ไม่รับส่วนคริจากเลเวลแบบกายภาพ
- สเตตัสพื้นฐานอัปได้ 1–99; แต้มต่อการอัปหนึ่งจุดคือ `floor((current − 1)/10)+2`
- DEX รวม 150 ตัดเวลาร่าย; ส่วนเกินมีผลต่อจังหวะ multi-hit ตามคำอธิบาย Wiki; ASPD cap 193
- HP regen มี tick และช่วงหยุดหลังโดนโจมตี ส่วน SP regen ไม่เพิ่มจาก INT โดยตรงตามหน้าอธิบาย

สูตรเหล่านี้คือสูตรที่เอกสารแสดง ยังไม่ได้ตรวจลำดับ rounding และ stacking ทั้งหมดในเกมจริง [Combat](https://lumivaraonline.com/wiki/#combat)

#### ตัวอย่างการอ่านสกิลที่ต้องเก็บมากกว่าตัวเลขดาเมจ

หน้า Skills แยกประเภทเป้าหมาย SP ระยะ cooldown และ rank; บางท่าใช้ ASPD เป็นจังหวะ บางท่ามี cooldown ตายตัว ในการปรับ Armageddon Starburst จาก rank 1 เป็น 10 ใน Wiki จำนวน hit เปลี่ยน 1→10, SP 15→42 และเวลาร่ายที่แสดงเปลี่ยนด้วย นี่เป็นการยืนยันตัวเลือกใน Wiki ไม่ใช่การ cast ในเกม

รายละเอียดที่มีผลต่อ build ได้แก่ damage type, element, hit count, target geometry, cast/channel timing, status proc, immunity, boss scaling และความสัมพันธ์กับอาวุธ ไม่ควรสร้าง `skillDamage` ช่องเดียวแล้วเติมคำบรรยายทีหลัง [Skills](https://lumivaraonline.com/wiki/#skills)

#### กติกาใหม่ที่มีผลต่อสมมติฐานการต่อสู้

ประกาศล่าสุดให้มอนมี stat sheet เฉพาะชนิด รวม MATK และระยะยิง; มอนบางกลุ่มมีเกราะและ HIT จึงใช้กติกาหลบต่างจากมอน HIT 0 ท่าธาตุมอนอิง MATK แล้ว ส่วน aggro พิจารณาดาเมจ การฮีล และ taunt พร้อม threshold เปลี่ยนเป้า ไม่ควรใช้แบบจำลอง “ทุกมอนวิ่งประชิดคนที่ตีล่าสุด” อีกต่อไป [Monster balance](https://lumivaraonline.com/changelog/#2026-10-02-monster-stat-sheet), [Aggro](https://lumivaraonline.com/changelog/#2026-10-02-skill-rebalance-aggro)

#### สเปกใหม่ที่เสนอให้ Xexoria

กำหนด damage pipeline เป็นเอกสารที่ executable test อ่านได้ เช่น `eligibility → hit resolution → base coefficient → crit → defense → elemental interaction → target modifiers → shield → HP` ลำดับนี้เป็นข้อเสนอ ไม่ใช่สิ่งที่พิสูจน์ว่า Lumivara ใช้

ทุกรายการต้องมีหน่วยชัดเจน: percent เทียบ percentage points, pixels เทียบ tiles, interval เทียบ attacks-per-second, per-cast เทียบ per-hit กำหนด rounding เพียงจุดที่จำเป็น และใช้ข้อมูลเดียวกันสร้าง tooltip, combat log และ Wiki

### 4.3 ธาตุ คอมโบ และสถานะ

#### สิ่งที่ Wiki อธิบาย

มีธาตุปฏิกิริยาหกแบบ ออร่าแต่ละธาตุอยู่บนมอน 6 วินาทีและ refresh แยกกัน คอมโบไม่กินออร่า; hit ที่เข้าเงื่อนไขจึงเรียกซ้ำได้ เมื่อมีหลายคู่ที่ใช้ได้เลือกคู่กับออร่าล่าสุด การ miss และดาเมจต่อเนื่องไม่สร้างปฏิกิริยาใหม่

ผลคอมโบครอบคลุมตัวคูณดาเมจ freeze, burn แบบพื้นที่, ลดพลังโจมตี และโล่ปาร์ตี้; มีข้อจำกัดเฉพาะ Leader และคอมโบไม่ทำงานใน PvP เคลือบอาวุธช่วยให้โจมตีปกติหรือสกิลไม่มีธาตุเข้าร่วมระบบนี้ ส่วนเคลือบเกราะใช้ฝั่งรับดาเมจ

ตารางสถานะแยก debuff, buff, immunity และผลแบบสะสม เช่น Venom; เวลาในตารางรวมกับเวลาของสกิลอาจไม่ตรงกัน ต้องเก็บ source ของสถานะด้วย [Elements](https://lumivaraonline.com/wiki/#elements), [Status](https://lumivaraonline.com/wiki/#effects)

#### ประเด็นลึกที่ควรทดสอบ

- การเรียกปฏิกิริยาทุก hit สามารถทำให้ multi-hit ได้ประโยชน์มากกว่า single-hit แม้ total coefficient เท่ากัน
- กติกา “ออร่าล่าสุดชนะ” อาจทำให้สมาชิกคนที่สามเปลี่ยนคอมโบของสองคนแรกโดยไม่ได้ตั้งใจ ต้องสื่อสารบน HUD
- ถ้า snapshot ATK/MATK เมื่อสร้างโล่ ต้องระบุว่า refresh แล้วใช้ค่าใหม่หรือไม่ และใครเป็นเจ้าของ contribution
- ต้องแยก `element tag` จาก `status tag`; พิษไม่จำเป็นต้องเป็นธาตุ และ freeze ไม่จำเป็นต้องหมายถึงธาตุน้ำแข็ง
- ทำ reaction budget ต่อ cast หรือ per-target cooldown เป็นตัวเลือกทดลองของ Xexoria เพื่อควบคุมความถี่ ไม่ควรกำหนดตาม Lumivara โดยอัตโนมัติ
- ห้ามให้ splash, DoT หรือ retaliation เรียก reaction ต่อกันไม่สิ้นสุด ต้องกำหนด `can_trigger_reaction` และ ancestry ของ damage event

### 4.4 มอนสเตอร์ Leader และบอสโลก

#### มอนธรรมดาและ Leader ตาม Wiki

มอนปกติในรายการระบุรอบเกิดใหม่ 5 วินาที; Elite เป็น variant ที่มีโอกาสเกิดแทนมอนปกติ พร้อม HP/ผลตอบแทนสูงขึ้น Leader เป็นสายพันธุ์ที่แรงที่สุดของพื้นที่ มี 2 ตัวต่อแผนที่ต่อ channel/region เกิดใหม่หลังตาย 5 นาทีและเปลี่ยนจุดเกิด

Leader ใช้ตัวคูณจาก species ต้นแบบ มี CC immunity บางชนิด และต้องแยกตาราง spawn ออกจากข้อมูล species การเปิด popup Leader Amber Beetle แสดงแหล่งเกิด Verdant Forest ตาราง drop และเกณฑ์ HIT/FLEE แต่ไม่ให้พิกัดเกิดตายตัว ค่าตัวเลขมอนใน Wiki ต้องระวังการล้าหลังประกาศใหม่ [Monsters](https://lumivaraonline.com/wiki/#monsters), [Leader detail](https://lumivaraonline.com/wiki/#monsters/amber-beetle), [Drops](https://lumivaraonline.com/wiki/#drops)

#### Nocthar ตามประกาศวันที่ 2 ตุลาคม

บอสโลกนี้ต้องให้ทีมงานเรียก ไม่ได้เกิดตามรอบ Leader ประกาศระบุ 3 เฟสและ 11 สกิล มี ground telegraph, การกระจายตัว/รวมตัว, adds และช่วงปลายไฟต์; ไม่มีผู้สู้หนึ่งนาทีจะ reset รางวัลผ่านจดหมายพิจารณาการตี ฮีล และยั่วยุ รวมโบนัสผลงานสูง/ตีปิด จึงเป็นอีกชนิดของ encounter ไม่ใช่ Leader ที่เพียงเพิ่ม HP [Nocthar](https://lumivaraonline.com/changelog/#2026-10-02-world-boss-nocthar)

**ยังไม่ทราบจากหน้าที่อ่าน:** threshold เข้าเฟสครบทุกช่วง, damage coefficient ครบทุกท่า, ระยะ/เวลาของ telegraph ทั้งหมด, สูตรคะแนน contribution, minimum contribution, กรณี disconnect/death, คะแนน overheal, ความสัมพันธ์โบนัส top-three กับ last-hit และกติกาจดหมายซ้ำ ยังไม่มีการเห็น Nocthar spawn หรือจบไฟต์ในการทดลองนี้

#### ข้อเสนอ Xexoria

แยก enemy entity เป็น `species + variant + encounter controller` ให้ Leader ใช้ controller ง่าย ส่วน event boss ใช้ state machine ของตนเอง ตัวละครบอส ฉาก สัญญาณและท่าต้องออกแบบใหม่

โครง encounter แนะนำ: `dormant → announced → engaged → phase transition → defeated / reset / administratively ended` ทุก transition ต้องมี owner, timer, reset policy และ reward state รองรับการหยุดกิจกรรมโดยไม่ทิ้งศัตรูหรือ mail ค้าง

หลีกเลี่ยงรางวัลที่ทำให้ healer/tank ต้องแย่ง last hit; ถ้ามี bonus เฉพาะอันดับ ให้ทดลองเทียบกับโบนัสตาม role contribution และกำหนดจำนวน reward recipients จากการมีส่วนร่วมที่ตรวจสอบได้

### 4.5 แผนที่และ progression

Wiki แสดงพื้นที่ล่า 11 แห่งเรียงช่วงมอนตั้งแต่ Verdant Forest 1–20 จน Stormcrest Peaks 250–270 โดยมีป่า หิมะ ทะเลทราย บึง ภูเขาไฟ และถ้ำคริสตัล แต่โลกเป็น portal graph ไม่ใช่เส้นตรงตามเลเวล เช่นป่าเริ่มต้นเชื่อมไปพื้นที่ที่สูงกว่ามากผ่านประตู และมีเมือง สนามฝึก กับสนาม PvP เป็นปลายทางเพิ่มเติม

Base cap ในคู่มืออยู่ที่ 120 ขณะที่เลเวลมอนสูงกว่านั้นได้; อย่าแปลป้ายช่วงมอนเป็น level requirement ของผู้เล่นโดยไม่มีหลักฐาน การเก็บ Job และการปรับ gear จึงน่าจะมีบทบาทต่อการไปพื้นที่ปลายเกม แต่ยังไม่ใช่เส้นทาง leveling ที่ทดสอบแล้ว [Maps](https://lumivaraonline.com/wiki/#maps), [Progress](https://lumivaraonline.com/wiki/#progress)

**ข้อเสนอ Xexoria:** แผนที่ควรมีสามข้อมูลต่างกันคือ level ของศัตรู, ความยากประเมินเทียบ build ปัจจุบัน และเงื่อนไขเข้า พอร์ทัลต้อง preview ปลายทางและความเสี่ยงก่อนเข้า มี safe arrival zone และทางกลับที่หาเจอง่าย พื้นที่ใหม่ควรเพิ่มพฤติกรรมศัตรูหรือโจทย์การจัด build ไม่ใช่เปลี่ยน palette และคูณ HP เพียงอย่างเดียว

### 4.6 อุปกรณ์ การตีบวก และวงจรของเหลือ

#### สิ่งที่อ่านพบ

อุปกรณ์ดรอปมี tier I–V และสุ่มค่าต่างจากของชื่อเดียวกันที่ซื้อจากร้าน; requirement ใช้เงื่อนไขทั้งชื่อไอเทมและ tier เซตสุ่มแยกจาก tier มีโบนัสตามจำนวนชิ้นและบางเซตซ้อน bonus ได้

Refine ถึง +10; ช่วงถึง +4 ปลอดภัย จากนั้นล้มเหลวมีความเสี่ยงทำลายชิ้นและการ์ดที่ฝัง Protection Stone ใช้เมื่อ fail เพื่อป้องกันการสูญเสีย Durability เป็นอีกระบบหนึ่ง: ของสึกจนไม่ให้ stat แต่ซ่อมได้ อย่าสับสนกับ refine destruction

Fusion ใช้ของดรอป tier เดียวกัน 5 ชิ้น เลือกชนิดผลลัพธ์แต่สุ่ม stat ใหม่ อาวุธกับหมวดเกราะแยกกัน Dismantle เปลี่ยนเป็น fragment ที่ใช้แทนวัตถุดิบหนึ่งชิ้นและ stack ได้ อุปกรณ์ใส่อยู่/ล็อก/ของร้านมีข้อจำกัดต่างกันตาม action; ข้อความ lock ของ Wiki บางส่วนถูกประกาศใหม่แทนที่แล้ว [Gear systems](https://lumivaraonline.com/wiki/#gear), [Equipment](https://lumivaraonline.com/wiki/#equipment)

#### การคำนวณความเสี่ยงจากตาราง Wiki

สมมติใช้ความสำเร็จ +5 ถึง +10 เท่ากับ 80%, 65%, 50%, 40%, 30%, 20% และแต่ละครั้งเป็นอิสระ:

- โอกาสที่ของ +4 ชิ้นเดียวขึ้นถึง +10 โดยไม่แตก = **0.624%**
- ถ้าป้องกันทุก fail และคงขั้นเดิม จำนวน attempt คาดหมายช่วง +4→+10 = **15.62 ครั้ง**
- Protection Stone ที่ใช้คาดหมาย = **9.62 ก้อน**
- จากค่า Silver ในตารางเดียวกัน ค่าใช้จ่ายคาดหมายเฉพาะช่วงนี้ ≈ **214,263 Silver** ไม่รวมราคาอุปกรณ์ หินตีบวก หรือ Protection Stone

ตัวเลข Silver ใช้ค่าธรรมเนียม +5 ถึง +10 ในตาราง Wiki เท่ากับ 2,500, 3,600, 9,800, 12,800, 16,200 และ 20,000 Silver ตามลำดับ คำนวณผลรวมของค่าธรรมเนียมแต่ละขั้นหารด้วยโอกาสสำเร็จของขั้นนั้น

นี่เป็น expected value ไม่ใช่จำนวนที่การันตี และใช้ไม่ได้ถ้า runtime มี pity, rate modifier หรือกติกาอื่นที่เอกสารไม่บอก

#### ข้อเสนอ Xexoria

ระบบปรับปรุงของควรมี preview แบบ delta และแสดงว่าอะไรหาย/อะไรเก็บไว้หลังทำ ก่อน bulk action ให้ preview รายการจริง ไม่อาศัยคำว่า “ตามตัวกรอง” เพียงอย่างเดียว ควรมี item provenance และปกป้องของเพิ่งซื้อ ของได้จากผู้อื่น ของใส่อยู่ รวมถึงของที่มีมูลค่าสูงโดย default

พิจารณาต้นแบบ refine แบบสะสมความคืบหน้าหรือเสียเฉพาะวัตถุดิบก่อนทดลองระบบแตกถาวร หากใช้ความเสี่ยงแตก ต้องสื่อสาร cumulative risk และต้นทุน ไม่ใช้แค่สีปุ่มเขียว/แดง ส่วน fusion ต้องไม่สร้างการวน arbitrage ระหว่างซื้อขาย NPC และ salvage

### 4.7 การ์ด ของใช้ และวัตถุดิบ

Wiki มีการ์ดที่เพิ่ม stat ตรง เพิ่มเปอร์เซ็นต์ สถานะเมื่อโจมตี และต้านสถานะ โดยกำหนดช่องที่ใส่ได้ บาง modifier รวม cap กับ gear บางอย่างไม่ stack การ์ดที่ใส่แล้วถอดไม่ได้ตามคำอธิบายทั่วไป แต่ประกาศเปลี่ยนระบบบางครั้งมี migration คืนของ จึงควรแยกกติกาการใช้งานจากกติกาย้ายเวอร์ชัน

หน้าไอเทมแสดง potion มี cooldown ร่วม, ammo ใช้ต่อการยิง/สกิล, เคลือบอาวุธและเกราะ, refine material และ fragments ส่วนการ์ดจากซอง LM-01 มีประกาศภายหลังจำกัดเฉพาะอาวุธมือขวา รวมอาวุธสองมือ จึงไม่ควรถือว่าข้อความ “หนึ่งช่องทุกไอเทม” ครอบคลุมทุกกรณี [Cards](https://lumivaraonline.com/wiki/#cards), [Items ใน Wiki](https://lumivaraonline.com/wiki/), [แก้ช่องการ์ด LM-01](https://lumivaraonline.com/changelog/#2026-10-02-card-pack-weapon-only)

**ข้อเสนอ Xexoria:** ใช้ compatibility rules เชิงข้อมูลสำหรับ slot/weapon group/card family พร้อมแสดงเหตุผลเมื่อใส่ไม่ได้ รักษาการ์ดและการอัปเกรดเป็น subentity ที่ตาม item instance ไป ไม่รวมไว้ในชื่อ string ระบบ migration ต้องคืนของอย่าง idempotent และทดสอบกระเป๋าเต็มก่อน deploy

### 4.8 ดรอป เศรษฐกิจ และ reward fairness

#### กติกาที่เอกสารบอก

คู่มือดรอปแยกหมวดวัตถุดิบ ของใช้ gear การ์ดและของพิเศษ มีเงื่อนไข level บางหมวด และ species ที่เพิ่มน้ำหนักของ slot บางประเภท การดรอป gear ถูกอธิบายเป็นสุ่ม slot ก่อนชนิดไอเทม; อาวุธแบ่งสัดส่วนตามอาชีพเพื่อไม่ให้สายที่มีชื่ออาวุธมากได้เปรียบ

ค่าฐานที่สำคัญใน Wiki คือ gear 1.25% และการ์ดประจำมอน 0.01% ต่อ kill ก่อน modifier ที่เกี่ยวข้อง แต่คำอธิบาย independence ของ popup ยังขัดกับคู่มือ [Drops](https://lumivaraonline.com/wiki/#drops)

#### ความหมายจริงของเปอร์เซ็นต์ต่ำ

สมมติ Bernoulli อิสระและไม่มี pity:

| โอกาสฐาน | จำนวน kill ที่มีโอกาสได้อย่างน้อยหนึ่งชิ้น 50% | จำนวน kill ที่มีโอกาส 95% |
|---|---:|---:|
| gear 1.25% | 56 | 239 |
| การ์ด 0.01% | 6,932 | 29,956 |

ฆ่า 10,000 ตัวที่โอกาสการ์ด 0.01% มีโอกาสได้อย่างน้อยหนึ่งใบประมาณ **63.2%** ไม่ใช่ครบหนึ่งหมื่นแล้วต้องได้ ความเร็วฆ่า ช่วงเดินหา ความหนาแน่น spawn และโบนัสจึงจำเป็นก่อนแปลงจำนวน kill เป็นชั่วโมง

#### กระเป๋า ตลาด และช่องทางเงิน

Wiki แยก Silver กับ Gold; มี market, direct trade, ค่าลงขาย, ภาษี และจดหมายรับเงิน/คืนของ กระเป๋ามีทั้ง slot กับ weight; น้ำหนักสูงถึง threshold กระทบการต่อสู้ Premium ลด friction หลายอย่าง เช่นบริการจากระยะไกลและภาษี พร้อม EXP/weight bonus จึงไม่ควรสรุป “cosmetic-only” จากข้อความการตลาดของเกม

สูตรน้ำหนักใน Wiki รวม level, STR, passive และ Gym Pass แล้วมีตัวคูณ Premium; ขณะเดียวกัน passive Weight Training อ้างโบนัส ATK จาก max carry weight นี่เป็น **dependency ที่ต้องทดสอบ** ว่า weight ที่ซื้อมีผลถึง ATK หรือถูกตัดออกจากสูตร ไม่ใช่หลักฐานยืนยัน pay-to-win ใน runtime [Economy](https://lumivaraonline.com/wiki/#economy), [Passives](https://lumivaraonline.com/wiki/#progress)

#### สเปกเศรษฐกิจสำหรับ Xexoria

สร้าง ledger แยก faucet/sink/transfer; ตลาดและ direct trade เป็นการย้ายเงิน ส่วน tax และค่า NPC เป็น sink ต้องติดตาม gross และ net ไม่ใช้ยอดเงินรวมแทนทั้งหมด การเพิ่ม drop rate ส่งผล supply, ราคาตลาด, เวลาเต็มกระเป๋า และความถี่ salvage พร้อมกัน

กำหนดนโยบาย monetization ก่อนสร้าง stat graph หากต้องการขาย convenience จริง ต้องกันเส้นทางที่ convenience กลายเป็น combat power ทางอ้อม เช่น weight→ATK, premium→slot→set uptime หรือ remote repair→farm uptime แล้วสื่อสารผลกระทบที่ยังเหลืออย่างตรงไปตรงมา

### 4.9 ปาร์ตี้ กิล และ PvP

Wiki ระบุปาร์ตี้สูงสุด 12 คน แบ่ง EXP ให้สมาชิกมีชีวิตในแผนที่เดียวกัน โดยมี level-gap eligibility เทียบคนทำดาเมจสูงสุดและโบนัสตามจำนวนสมาชิกที่ผ่านเงื่อนไข ส่วน loot ปกติให้สิทธิ์คนทำดาเมจสูงสุดชั่วคราวก่อนเปิดให้คนอื่นเก็บ

กิลมี progression และโบนัส EXP โดยใช้การบริจาค EXP/เงิน; PvP เป็นพื้นที่สมัครใจ มี protection ตอนเข้าและข้อยกเว้น friendly fire ไม่ควรใช้ค่า damage scaling ของ PvP มาคาดการณ์ PvE หรือ world boss

เอกสารยังไม่อธิบายครบว่า party sharing รวมกับ contribution ของหลายปาร์ตี้อย่างไร และไม่ได้ให้ loot-distribution mode ครบทุกกรณี [Social](https://lumivaraonline.com/wiki/#social), [พื้นฐาน loot](https://lumivaraonline.com/wiki/#mechanics)

**ข้อเสนอ Xexoria:** แสดง eligible members พร้อมเหตุผลที่ไม่ได้รับ reward ก่อนหรือระหว่าง encounter ให้ healer/tank ได้ contribution ที่สัมพันธ์กับประโยชน์จริง ใช้ effective healing แยก overheal และป้องกันการวนฮีลให้คะแนนกันเอง การหาร EXP ต้องชัดเจนว่าคูณโบนัสก่อนหรือหลังแบ่ง และ rounding ต้องไม่ทำให้ reward เพิ่มจากการแยกปาร์ตี้

### 4.10 เควสต์ ความตาย Auto Play และ offline

Tutorial ใน Wiki เป็นลำดับสอนโจมตี เก็บของ อัป stat ใส่ gear ใช้ยา เรียน skill เปลี่ยน job ค้าขายและเดินทาง Daily check-in นับครั้งรับ ไม่ใช่ streak ที่ขาดแล้วเริ่มใหม่; daily hunt ให้ refine material

ความตายตามคู่มือไม่เสีย EXP/ไอเทม มีทางกลับเมือง ชุบที่เดิมโดยเสีย Silver หรือให้ Cleric ช่วย Auto Play มี filter มอน/loot การใช้ heal/potion และ auto-dismantle; การเก็บของด้วย pet ผูกกับ Premium [Getting started](https://lumivaraonline.com/wiki/#mechanics)

FAQ ระบุว่า bot รันใน browser และหน้าเกมที่ซ่อนอาจถูก browser พัก จึง **ไม่ใช่หลักฐานของ server-side offline farming** ส่วนเวลาบัฟ EXP/Drop ยังมีข้อขัดแย้ง: FAQ บอกว่าเดินต่อเมื่อ offline แต่ประกาศ 28 ก.ย. ให้ pause และไม่พบประกาศย้อนกลับภายหลังในประวัติที่อ่าน ต้องจับเวลา runtime ก่อนยืนยันเรื่องนี้ และต้องแยก timer ของบัฟออกจากการทำงานของ bot [FAQ ข้อ 27–28](https://lumivaraonline.com/faq/), [ประกาศ pause บัฟ](https://lumivaraonline.com/changelog/#2026-09-28-boost-scroll-pause-offline)

## 7 ความเชื่อมโยงของระบบ

1. **ล่า → เก็บของ → น้ำหนัก/ช่อง → Pet/Storage/ย่อยของ** มีหลายปลายทางและหน้าต่างที่เปิดปิดเป็นคู่ แต่ต้องรักษา ownership และจำนวนของชุดเดียว โดยเฉพาะเพดานรวม pet กับผู้เล่นและข้อยกเว้นของย่อยอัตโนมัติ
2. **Base/Job → Skill Point → skill/passive → ชุดอาชีพ → equipment** แต่ละชั้นปลดล็อกต่างกัน ต้องแสดงว่าปุ่มที่ล็อกขาดอะไร และเมื่อเปลี่ยนชั้นหนึ่งต้อง recompute อีกชั้นโดยไม่ทิ้ง state เก่า
3. **Daily → Refine Stone → Blacksmith → ความเสี่ยง refine → Protection Stone** เป็นวงจร progression ที่เชื่อมรางวัลฟรีกับระบบป้องกันพรีเมียม รายงานนี้ยังไม่พิสูจน์ refine จริง
4. **monster drops ธาตุ → Quest Exchange → coating → Bot potion/coating rules** เป็นตัวอย่างของของเก่าที่มีปลายทางใช้ต่อ แต่ต้องบอกก่อน exchange ว่าจะใช้กองใดและผลที่แทนธาตุเดิมคืออะไร
5. **Gold → Premium/สินค้า → mail/entitlement → ประวัติ/refund** ความสอดคล้องนโยบายมีความสำคัญพอ ๆ กับการซื้อสำเร็จ
6. **Map → zone ปัจจุบัน → monster choices/quest/party/minimap** การย้ายฉากต้องอัปเดตทุกระบบที่พึ่งพื้นที่ ไม่จบเพียงฉากภาพเปลี่ยน
7. **rename → identity คงที่ → friend/guild/party/mail/market** ชื่อแสดงผลควรเปลี่ยนได้โดยไม่เป็น key ของ ownership หรือความสัมพันธ์

8. **ตลาด NPC/ผู้เล่น → bag/pet/storage → item ownership → trade log** มีแหล่งราคาและประวัติหลายแบบ ต้องแยกให้ผู้เล่นทราบว่าราคาจากใครและประวัติถูกเก็บที่ใด
9. **party/guild → membership → EXP/loot/contribution → progression** การเข้ากลุ่มกับการได้รับโบนัสมีเงื่อนไขต่างกัน และกติกาต้องถูกบังคับใช้เหมือนที่ UI อธิบาย
10. **mail/daily/community reward → สิทธิ์บัญชี → ของเข้า bag → บัฟ** ความพร้อมของรางวัลไม่เท่ากับสิทธิ์รับ และต้องกันรับซ้ำทุกทางเข้า

**เส้นทางที่ยังไม่ได้เห็น UI:** พบชื่อ Fusion Master ในคำอธิบาย Premium/บริบท NPC แต่หาและเปิดหน้าต่าง Fusion ไม่สำเร็จในการตรวจนี้ จึงไม่อธิบาย recipe, reroll หรือ commit flow ว่าได้ทดลอง รายละเอียดที่มาจาก Wiki ต้องแยกเป็นหลักฐานคู่มือ

รายการข้างต้นเป็นการสังเคราะห์จากข้อความและทางเข้า UI ที่พบ ไม่ใช่การรับรองว่าการเชื่อมต่อ backend ทุกเส้นผ่านการทดสอบแล้ว

## 8 ลำดับงานสำหรับ Xexoria

ลำดับนี้เป็นข้อเสนอสำหรับเกม 3D ที่เน้นเล่นเอง ยังไม่ได้ตรวจ repository เพื่อยืนยันว่ารายการใดมีแล้ว “ทำตอนนี้” จึงหมายถึงตรวจของเดิมก่อน แล้วเติมช่องว่างตามเกณฑ์ผ่าน ไม่ใช่เขียนใหม่ทุกระบบ

### P0 ทำให้แกนเกมครบและเชื่อถือได้

#### P0 01 การเดินและกล้อง

**ทำ:** keyboard/touch adapter ส่ง action ชุดเดียว, กล้องติดตามพร้อม collision, หยุดเดินเมื่อเสีย focus, ไม่รับ movement ขณะพิมพ์ใน chat

**เกณฑ์ผ่าน:** เดินเลียบผนัง/ขึ้นทางลาด/เลี้ยวมุมไม่ติดซ้ำ; เปิดกระเป๋าหรือพิมพ์แล้วตัวละครไม่หลุดเดิน; หมุนกล้องใกล้กำแพงแล้วยังเห็นตัวละคร; กลับจากแท็บอื่นแล้วไม่มีปุ่มค้าง

**พึ่งพา:** movement simulation และรูปแบบ state synchronization ที่มีอยู่

#### P0 02 ต่อสู้หนึ่งชุดที่อ่านออก

**ทำ:** โจมตีพื้นฐานหนึ่งแบบ สกิลหนึ่งแบบ หลบหนึ่งแบบ ศัตรูหนึ่งตัวที่มีท่าเตือน เป้าหมาย/ระยะ/เวลาคูลดาวน์อ่านชัด

**เกณฑ์ผ่าน:** การฟันหนึ่งครั้งให้ผล damage ครั้งเดียว; รับผลจาก server แล้ว HP/ตัวเลข/เสียงตรงกัน; อยู่นอกระยะหรืออยู่ระหว่าง cooldown แล้วเห็นเหตุผล; หลบและเปิด UI ไม่ทำให้ input ค้าง; ลด effects แล้วยังเห็น telegraph

**พึ่งพา:** P0 01 และ server combat validation

#### P0 03 บทเรียนแรกแบบเล่นเอง

**ทำ:** เป้าหมายทีละข้อพร้อม marker และปุ่มคำแนะนำตาม binding ปัจจุบัน ให้ของชิ้นแรกที่ใช้ได้จริง

**เกณฑ์ผ่าน:** ผู้เล่นใหม่จบเดิน/โจมตี/หลบ/เก็บ/ใส่ของได้โดยไม่เปิด wiki; ออกจากเกมแล้วกลับมาต่อขั้นเดิม; ข้ามและเปิดคู่มือใหม่ได้; ทำกิจกรรมก่อนเควสเปิดแล้วไม่ติดทางตัน

**พึ่งพา:** P0 01–02, inventory และ quest state

#### P0 04 กระเป๋าและอุปกรณ์ที่ไม่ทำของหาย

**ทำ:** ดูรายละเอียด ใส่/ถอด เปรียบเทียบของสองชิ้น ค้นหา/หมวดพื้นฐาน ล็อกของสำคัญ และแยกปุ่มทำลายออกจาก action หลัก

**เกณฑ์ผ่าน:** ดับเบิลคลิก/กดซ้ำ/คำขอซ้ำไม่สร้างของเพิ่ม; equip ส่งผลสเตตัสครั้งเดียว; การกระทำที่กติกา lock ห้ามถูกกันทั้ง UI และ server; เมื่อกระเป๋าเต็มยังรับรางวัลได้ด้วยนโยบายที่ชัดเจน; reconnect แล้วจำนวนของตรงกัน

**พึ่งพา:** item instance ID, ownership, atomic inventory mutation

#### P0 05 ปาร์ตี้เล็กที่ใช้งานได้ครบวงจร

**ทำ:** invite/accept/decline/leave, หัวหน้ากลุ่ม, online state, HP สมาชิก, marker ในโลก, เขต/instance ที่อยู่ และกติกา loot/EXP ที่อ่านก่อนเข้าร่วม

**เกณฑ์ผ่าน:** คำเชิญหมดอายุ/ปาร์ตี้เต็ม/หัวหน้าออกมีผลแน่นอน; accept ซ้ำไม่ซ้ำสมาชิก; สมาชิกหลุดแล้วกลับมาไม่เป็นผีค้าง; ย้าย instance แล้ว UI อัปเดต; คนไม่มีสิทธิรับผลประโยชน์เห็นเหตุผลก่อนเข้ากลุ่ม

**หมายเหตุ:** จำนวนสมาชิกควรเลือกตาม encounter และต้นทุนระบบเสียงของ Xexoria ไม่จำเป็นต้องตามจำนวนของ Lumivara

#### P0 06 ความปลอดภัยของ chat และ voice

**ทำ:** แยก Party/System, mute/block/report, rate limit, รายงานสถานะกำลังเชื่อมต่อเสียง/ปิดไมค์/ถูกปฏิเสธสิทธิ์ให้ชัด เสียงเป็นตัวเลือกเสริมของปาร์ตี้

**เกณฑ์ผ่าน:** คนที่ไม่ใช่สมาชิกเข้า voice room ไม่ได้; ออกจากปาร์ตี้แล้วถูกถอดสิทธิ์เสียง; reconnect ไม่ทิ้ง audio track เก่า; ปฏิเสธไมค์แล้วยังเล่นและใช้ข้อความได้; hotkey เกมไม่ทำงานขณะพิมพ์

**ที่มา:** เป็นข้อเสนอของ Xexoria ไม่พบหลักฐานระบบ voice ของ Lumivara ในหน้าที่ตรวจ

#### P0 07 โหลด บันทึก และต่อกลับ

**ทำ:** loading state ที่บอกขั้นตอน, save status, retry ที่ไม่สร้างตัวละครซ้ำ, reconnect และกลับเข้าสู่สถานะ server ล่าสุด

**เกณฑ์ผ่าน:** refresh ขณะรับรางวัลไม่รับซ้ำ/หาย; ตัดเน็ตชั่วคราวแล้วต่อกลับได้; session หมดอายุมีทางกลับ; client ไม่รายงานว่าสำเร็จเมื่อ server ปฏิเสธ; Guest มีคำเตือนการสูญเสียการเข้าถึงและทางผูกบัญชีที่เข้าใจง่าย

#### P0 08 อ่านจอง่ายและวัดจริง

**ทำ:** HUD scale, ปิด screen shake, ปรับขนาดตัวอักษร, โหมด effects ต่ำ และการเก็บ frame time/network error แบบไม่เก็บข้อมูลส่วนตัวเกินจำเป็น

**เกณฑ์ผ่าน:** ทดสอบ desktop และโทรศัพท์จริงที่ระบุรุ่น; ทำฉากเดินเดี่ยว ฉากปาร์ตี้ และฉาก effects หนาแน่นเดียวกัน; รายงาน median/p95 frame time, memory และ network stalls พร้อมเงื่อนไข; อย่าใช้ตัวเลข FPS ครั้งเดียวตัดสินว่า “รองรับ MMO แล้ว”

### P1 เพิ่มเมื่อวงจร P0 ผ่านแล้ว

#### P1 01 แผนที่ที่ตอบว่าควรไปไหน

แสดงพื้นที่แนะนำ เป้าหมายเควส ทางกลับเมือง สมาชิกปาร์ตี้ และค่าเดินทางก่อนยืนยัน เกณฑ์ผ่านคือเลือกเป้าหมายแล้วรู้ว่าเดินเอง วาร์ปได้ หรือถูกล็อกเพราะอะไร โดยไม่ต้องเดาไอคอน

#### P1 02 Preview สกิลและ loadout

ใช้ pending points → review → apply พร้อม reset preview แยกจาก reset build จริง เกณฑ์ผ่านคือสลับหน้าหรือ reconnect แล้วไม่มีการใช้แต้มเงียบ ๆ และทุก change ผ่าน server validation

#### P1 03 หาปาร์ตี้ตามกิจกรรม

แสดงเป้าหมายกลุ่ม บทบาทที่ขาด ภาษา instance และเงื่อนไขเข้าร่วม ให้ผู้เล่นกรองสิ่งที่เข้าร่วมได้ก่อน เกณฑ์ผ่านคือผล stale/กลุ่มเต็มมีข้อความที่เข้าใจและ refresh ได้ ไม่ส่งคำขอซ้ำโดยไม่ตั้งใจ

#### P1 04 ช่องทางใช้ของเหลือแบบคาดการณ์ได้

เริ่มจากย่อยของเป็นวัสดุและคราฟต์แบบเลือกผลลัพธ์ ก่อนเพิ่มสุ่มหลายชั้น เกณฑ์ผ่านคือ preview บอกทุกชิ้นที่จะหายและผลลัพธ์ ของล็อก/ใส่อยู่/มีการ์ดสำคัญไม่ถูกเลือกอัตโนมัติ และคำขอซ้ำไม่ย่อยซ้ำ

#### P1 05 คอมโบที่ทำให้เพื่อนช่วยกันจริง

เริ่มด้วยคู่สถานะสองอย่าง เช่น ทำให้เปียกแล้วใช้ไฟฟ้า โดยตั้งชื่อ/ภาพ/ตัวเลขของ Xexoria เอง ไม่ต้องยกตารางธาตุทั้งหมดมา เกณฑ์ผ่านคือสมาชิกเห็นสถานะและเวลาที่เหลือ คนทำคอมโบได้ feedback ชัด และ server ตัดสินลำดับการชนกันอย่างแน่นอน

#### P1 06 คู่มือที่ดูแลได้

สร้าง bestiary/item help จากข้อมูล balance ชุดเดียวกับเกม ระบุเวอร์ชันและคำอธิบายสั้น เกณฑ์ผ่านคือชื่อปุ่ม เงื่อนไขใส่ของ และ requirement ในคู่มือไม่ขัดกับเกมหลังเปลี่ยนข้อมูล

### P2 ทำภายหลังหรือยังไม่ต้องทำ

- **Auto Play เต็มระบบ:** ต้องตัดสินก่อนว่า Xexoria ต้องการเป็น active action MMO หรือ idle MMO เพราะเปลี่ยนทั้งเศรษฐกิจ จังหวะเกม และปริมาณ server simulation
- **ตลาดผู้เล่นและเงินพรีเมียม:** รอ item ledger, anti-duplication, ภาษี/แหล่งเงิน, moderation และกระบวนการ support พร้อมก่อน
- **หลายอาชีพพร้อม passive ข้ามสาย:** เพิ่มหลังทดสอบได้ว่าอาชีพเริ่มต้นแต่ละแบบสนุกและมีหน้าที่ในปาร์ตี้
- **กิลด์ การเมือง และ PvP ขนาดใหญ่:** รอปาร์ตี้เล็ก/netcode/การรับรายงานให้มั่นคง
- **ระบบของแตกถาวรและขายการป้องกัน:** ยังไม่แนะนำใน vertical slice เพิ่มความเครียดและงานกู้คืนก่อนพิสูจน์ว่าคุ้มค่าความสนุก
- **สุ่มของหายากมากและแคมเปญเร่งเติม:** ไม่ควรเป็นสิ่งแรกที่นำมาเป็นต้นแบบ ให้พิสูจน์ core loop ก่อน
- **หน้าตา UI และงานภาพเหมือนต้นฉบับ:** ข้าม ให้ใช้ identity ของ Xexoria และงานที่มีสิทธิ์ใช้อย่างชัดเจน

### ลำดับการลงมือและเกณฑ์ขยายขอบเขต

1. ตรวจของที่ Xexoria มีอยู่เทียบ P0 และเลือกฉากทดสอบกลางหนึ่งฉาก
2. ทำ vertical slice ให้จบ: เข้าเกม → รับเป้าหมาย → เดิน/สู้/หลบ → เก็บและใส่ของ → เล่นกับเพื่อน → ออกและกลับมาโดยข้อมูลไม่หาย
3. ปิด failure cases ก่อนเพิ่มคอนเทนต์: reconnect, double submit, full inventory, party full, permission denied และ UI focus
4. วัดบนอุปกรณ์เป้าหมาย แล้วจึงเพิ่มแผนที่ อาชีพ และระบบความก้าวหน้า
5. ใช้ playtest ดูว่าผู้เล่นติดตรงไหนจริง ไม่ใช้จำนวนเมนูหรือจำนวนฟีเจอร์ของเกมอ้างอิงเป็นเกณฑ์ความพร้อม

ต้นแบบแรกควรใช้หนึ่งพื้นที่ทดสอบ หนึ่งชุดการโจมตีและศัตรูหนึ่งแบบเพื่อพิสูจน์ P0 ก่อน เมื่อผ่านแล้วจึงขยายเป็นเมือง พื้นที่ล่าที่มีโจทย์ต่างกัน บทบาทปาร์ตี้จำนวนเล็กน้อย และ encounter ที่มี telegraph ตัวเลขขอบเขตควรเลือกตามกำลังทีมและผล playtest ไม่ใช้จำนวนแผนที่หรืออาชีพของเกมอ้างอิงเป็นเป้าบังคับ

## 9 สถาปัตยกรรมและสัญญาข้อมูลที่เสนอ

ส่วนนี้เป็นแบบเสนอ ไม่ได้ตรวจโค้ด Xexoria และไม่ได้สรุปเทคโนโลยี backend ของ Lumivara

**Babylon.js / client** รับ input, กล้อง, animation, VFX, UI และคาดการณ์การเคลื่อนที่เพื่อให้ตอบสนองเร็ว แต่ต้องยอมรับการแก้สถานะจาก server ไม่ถือยอดเงิน damage หรือ inventory ใน client เป็นความจริงสุดท้าย

**Rust / server** ถือข้อมูลตัวละคร ตำแหน่งที่ยอมรับได้ damage, cooldown, loot, quest, party และ ownership ตรวจ request ด้วย action ID/sequence แล้วตอบผลพร้อม reason code

**ข้อมูลขั้นต่ำที่ควรแยก:** Character, ItemDefinition, ItemInstance, AbilityDefinition, QuestProgress, Party และ PartyMembership ใช้ ID คงที่แทนชื่อที่เปลี่ยนได้ ส่วน display name แปลภาษาได้

**เหตุการณ์สำคัญ:** quest progress, inventory changed, equipment changed, party membership changed, action rejected และ reconnect snapshot การรับซ้ำต้องไม่สร้างผลลัพธ์ซ้ำ ส่วน UI อ่าน event เดียวกันเพื่อลด badge/ข้อความที่ขัดกัน

**ขอบเขตเสียง:** voice transport ไม่ควรเป็นผู้ตัดสินสิทธิ์ปาร์ตี้ สิทธิ์เข้าห้องและอายุ token ต้องตาม membership จากเกม การปิดไมค์หรือ voice ล่มต้องไม่ทำให้ combat/network state ของเกมล่มตาม

### 9.1 สัญญาข้อมูลที่ควรมีตั้งแต่ต้น

ตารางนี้เป็นข้อเสนอใหม่เพื่อให้ทีม Xexoria ตรวจของเดิมและเติมเฉพาะช่องว่าง ไม่ใช่การอ้างโครงสร้างภายในของ Lumivara

| ข้อมูลหรือขอบเขต | สิ่งที่ควรเก็บ | เงื่อนไขที่ต้องรักษา |
|---|---|---|
| Character กับ JobProgress | ID คงที่, Base progression, job ปัจจุบัน, แต้ม/สกิลแต่ละ job | เปลี่ยนชื่อหรืออาชีพไม่เปลี่ยนเจ้าของของและความสัมพันธ์ |
| ItemDefinition กับ ItemInstance | ชนิด, roll, tier, set, socket/card, refine, durability, bound/lock, provenance | instance อยู่ในตำแหน่งถือครองที่ถูกต้องเพียงแห่งเดียว |
| Loadout | gear, passive, hotbar และ appearance แยกตามขอบเขตที่เลือก | validate ทั้งชุดก่อน commit; ไม่มีการใช้แต้มจาก preview |
| Ability กับ CombatEvent | target shape, cost, timing, damage type/element, proc rule, source/ancestry | event เดิมให้ damage/reaction/reward ซ้ำไม่ได้ |
| Enemy กับ Encounter | species, variant, AI role, encounter state, spawn scope | reset ล้าง adds/status/contribution ตามนโยบายเดียวกัน |
| Party กับ Membership | role, leader, zone/instance, eligibility, permission revision | client และ voice ไม่ให้สิทธิ์เกิน membership ปัจจุบัน |
| InventoryLocation | bag, equipment, storage, pet, escrow, mail | ย้ายต้นทาง–ปลายทางสำเร็จพร้อมกันหรือไม่เกิดทั้งคู่ |
| RewardReceipt | encounter/quest ID, recipient, eligible reason, grant result | claim/reconnect/retry ให้ผลครั้งเดียวและตรวจย้อนกลับได้ |
| EconomyLedger | source, destination, sink, fee, escrow, transaction ID | เงินเข้าออกสมดุล; ข้อผิดพลาดไม่ใช้การเดาเพื่อชดเชย |
| BalanceRule กับ PolicyVersion | rule ID, effective version/time, supersedes, migration | UI, tooltip, Wiki และประวัติแสดงกติกาที่ใช้จริงชุดเดียวกัน |

### 9.2 แยก UI state จากผลธุรกรรม

หน้าที่โหลดข้อมูลควรแยก `loading`, `loaded-empty`, `loaded-data`, `stale` และ `error` โดยไม่แสดงเลขศูนย์ให้ดูเหมือนผลสำเร็จระหว่างยังโหลดอยู่ ส่วนธุรกรรมควรแยก `preview`, `submitting`, `committed`, `rejected` และ `outcome-unknown` การหลุดหลังส่งไม่ใช่เหตุผลให้ส่งคำขอใหม่โดยไม่มี idempotency key

ตัวอย่าง flow สำหรับการย่อยของที่เสนอ: เลือก filter → server หรือ authoritative model ประเมินรายการ → preview แสดงของและผลตอบแทน → ยืนยันด้วย instance IDs และ revision → ตรวจ ownership/lock/equipped อีกครั้ง → commit ผลครั้งเดียว → ส่ง receipt และ state revision กลับ หน้าต่างที่เปิดค้างต้องแจ้งเมื่อข้อมูลเปลี่ยนจน preview ใช้ไม่ได้

### 9.3 กล้อง การเคลื่อนที่และ input ของเกม 3D

Lumivara ช่วยให้เห็นหลักการยืนยันเป้าหมายและ stop state แต่ไม่ได้พิสูจน์ third-person camera ของ Xexoria ให้แยก input adapter, action mapping, movement prediction, server reconciliation และ camera collision ออกจากกัน กำหนดความหมายของ tap, hold, target selection และ cancel ให้ชัดตั้งแต่ต้น

การเสีย focus การพิมพ์ chat การเปิดเมนู การ KO และการเปลี่ยนพื้นที่ต้องเคลียร์ input ที่ค้างตามกติกาเดียวกัน หากเปลี่ยน key binding คู่มือและ tooltip ต้องเปลี่ยนตาม action ID เดียว ไม่ใช้ข้อความปุ่มที่เขียนแยกกัน

### 9.4 งาน migration ต้องครอบคลุมของนอกกระเป๋า

เมื่อแก้ slot การ์ด เซต สเตตัส อาวุธ หรือกฎ passive ต้องพิจารณาของที่อยู่ใน storage, pet, equipment, escrow, market และ mail ด้วย ใช้ migration version และ receipt ต่อ instance ป้องกันทำซ้ำ พร้อม reconciliation ตรวจจำนวนก่อน–หลัง การคืนของควรมีช่องทางรองรับกรณีกระเป๋าเต็ม และต้องอธิบายให้ผู้เล่นรู้ว่ามีอะไรเปลี่ยน

ความจำเป็นนี้มาจากประวัติการเปลี่ยนกฎหลายรอบของเกมอ้างอิง ส่วนรูปแบบข้อมูลและกลไก migration ข้างต้นเป็นข้อเสนอสำหรับ Xexoria

### 10.2 Combat และการซ้อนผล

- ใช้ target เดียวและค่า stat คงที่ทดสอบ hit, crit, defense และ pierce แยกทีละตัว แล้วค่อยทดสอบ interaction
- สำหรับ probability ใช้จำนวนตัวอย่างและ confidence interval; อย่าสรุปจากการตี 20 ครั้งว่าเปอร์เซ็นต์ถูก/ผิด
- จับคู่ single-hit กับ multi-hit ที่ total coefficient เท่ากัน แล้ววัด DPS, reaction count, healing และ SP restored ต่อวินาที
- ทดสอบ threshold ทุกขอบ เช่นก่อน/หลัง cap หนึ่งหน่วย ไม่ดูเฉพาะ build กลางช่วง
- ทดสอบ buff หมดระหว่าง multi-hit, สลับอาวุธระหว่าง cast, เป้าหมายตายก่อน projectile ถึง และ latency สูง

### 10.3 Threat และ reward

- คนทำดาเมจสูงสุดเปลี่ยนกลางไฟต์แล้ว party eligibility เปลี่ยนอย่างไร
- healer ช่วยหลายเป้าหมายที่สู้คนละกลุ่มมอน ต้องไม่คูณ aggro/contribution ซ้ำผิด
- ผู้เล่นเข้าไฟต์ช้า ตาย disconnect หรือย้ายแผนที่ก่อน kill ต้องได้ผลตามนโยบายที่แสดง
- last hit, top contribution และ mail grant ต้องเรียกซ้ำแล้วได้ผลเดียว ไม่สร้าง reward รอบที่สอง
- การ reset boss ต้องจัดการ adds, debuff, contribution และ ownership พร้อมกัน

### 10.4 เศรษฐกิจและการสูญเสียของ

- ตรวจ conservation ของเงินใน trade/market: เงินผู้ซื้อ เงินผู้ขาย tax และ escrow รวมกันต้องอธิบายได้
- ทดสอบการกด submit ซ้ำ คำสั่งมาช้า cancel ระหว่างขาย และ mail เต็ม/หมดอายุ
- ทดลอง bulk salvage กับ locked/equipped/newly purchased/socketed items; preview ต้องตรงกับผลที่ commit
- ตรวจวงจร buy→markup→sell, salvage→fusion→sell และ currency exchange ว่ามีช่องสร้างเงินไม่ตั้งใจหรือไม่
- จำลอง distribution เวลาได้ upgrade โดยดู median และ P90/P95 ไม่ใช้ค่าเฉลี่ยเพียงค่าเดียว

### 10.5 UX และการเข้าถึง

- Boss telegraph ต้องอ่านได้เมื่อเอฟเฟกต์ปาร์ตี้หนาแน่น และไม่พึ่งสีอย่างเดียว
- ค่าเปอร์เซ็นต์ต้องบอกว่าโอกาสต่อ hit, ต่อ cast, ต่อ kill หรือหลังเลือกหมวดแล้ว
- Auto ต้องมีสถานะ paused/out-of-ammo/overweight/path-blocked/server-disconnected ที่แตกต่างกัน
- Tutorial ต้องดึงชื่อปุ่มและ keybind จากระบบจริง ไม่ฝังข้อความปุ่มตายตัว
- Wiki/patch discrepancy ควรเป็น build gate: หาก mechanic เปลี่ยน ต้องมี migration test และเอกสาร version ใหม่ก่อนปล่อย

## 11 ตัวชี้วัดและเงื่อนไขขยายขอบเขต

- เวลาไปถึงการตัดสินใจ build ครั้งแรก และสัดส่วนผู้เล่นที่เข้าใจผลของตัวเลือก
- TTK ตาม role/ระดับ/ความยาก พร้อมสัดส่วนเวลาที่เดินหาเป้าหมาย
- skill uptime, potion consumption, SP sustainability และสัดส่วนดาเมจจาก reaction
- เวลาได้ upgrade ที่ใช้งานได้จริง แยกจากเวลาได้ gear ใด ๆ

เป้าตัวเลขควรกำหนดหลัง prototype playtest และขนาด session ที่ Xexoria ต้องการ ไม่ควรนำความเร็ว progression ของ Lumivara มาใช้โดยยังไม่มีข้อมูลเวลาฆ่า การเดินทางและจำนวนผู้เล่นของตนเอง

### 12.2 ยังไม่ผ่านการทดสอบ runtime

- การต่อสู้แบบควบคุมที่แยกหนึ่ง input ต่อผลลัพธ์ รวมถึงระยะ, hit confirmation, cooldown และหลบ; รอบนี้ยืนยัน targeted basic attack, normal kill และ KO ได้ แต่ไม่ใช่การตรวจทุกเงื่อนไขการต่อสู้/ตาย
- มอนชนิดอื่น Elite, Leader และ world boss ใน encounter จริง; Dew Bunny ที่ฆ่าได้หนึ่งตัวไม่แทนพฤติกรรมของทั้งเกม และไม่ใช้ชื่อ/กติกาใน Bot Settings แทนหลักฐานต่อสู้
- การเปลี่ยนอาชีพ ใส่ของ ใส่ passive, skin และคำนวณ stats หลัง Apply
- party/guild/trade/PvP กับอีกบัญชีและสิทธิ์ของสมาชิกแต่ละแบบ
- ซื้อขาย/แลก/ย่อย/refine/mail claim ภายใต้ bag full, disconnect และคำขอซ้ำ
- อุปกรณ์มือถือและ gamepad จริง รวมถึงความลื่นและความแม่นของ input
- หน้าระบบ Fusion, achievement ที่อาจอยู่เส้นทางอื่น และการเปลี่ยน channel/region; การไม่พบ UI ในรอบนี้ไม่ใช่ข้อสรุปว่าไม่มีฟีเจอร์
- target HUD, telegraph และ loot ของ Leader/world boss รวมถึงหุ่นฝึกทุกแถวระดับที่หน้า Map อธิบาย
- backend, security, anti-duplication, latency และจำนวนผู้เล่นพร้อมกันแบบทดสอบควบคุม

### 12.3 เอกสารยังตอบไม่ครบ

ไม่พบคำตอบครบหรือยังยืนยันไม่ได้ในรอบนี้:

1. สูตร raw ATK/MATK/MaxHP/MaxSP ทั้งชุดและลำดับรวม additive/multiplicative modifier
2. สูตร ASPD→attack interval ที่ครบทุกช่วง รวม projectile travel time และ animation cancel
3. snapshot หรือ dynamic scaling ของ DoT/โล่/ออร่าหลังสลับ gear หรือ job
4. สิทธิ์ loot เมื่อมีหลายปาร์ตี้ การให้คะแนน support และการป้องกัน last-hit abuse
5. repeatability และ seed ของ loot; มี pity หรือ hidden modifier หรือไม่
6. offline simulation ฝั่ง server, crash recovery และความรับประกัน persistence ของ Guest
7. Nocthar phase thresholds/telegraph timing/reward eligibility ครบทุกกรณี
8. วัตถุดิบ crafting นอกเหนือจาก fusion, refine, fragment และ exchange ที่เอกสารระบุ
9. ผลบาลานซ์ของ paid convenience ต่อ stat ที่ derive จาก weight
10. สาเหตุที่ Wiki และ patch notes ไม่สอดคล้องกัน รวมถึง version ของข้อมูลที่กำลังแสดง

การไม่พบข้อมูลไม่ได้แปลว่าไม่มีระบบนั้น และการมีปุ่ม/คำอธิบายไม่ได้แปลว่าทดลองครบแล้ว

### 12.4 การใช้เป็น reference โดยรักษาเอกลักษณ์ของ Xexoria

สิ่งที่นำไปใช้ได้คือหลักการทั่วไป โครงสร้างการตัดสินใจ และคำถามที่ต้องพิสูจน์ ให้สร้างชื่ออาชีพ ศัตรู โลก แผนที่ ภาพ UI เสียง เนื้อเรื่อง โค้ด และตัวเลขบาลานซ์ของ Xexoria ขึ้นใหม่ ไม่ใช้ภาพหน้าจอเป็น assets ของเกม และไม่ตีความรายงานนี้เป็นสิทธิ์คัดลอกทรัพย์สินของ Lumivara

ข้อสรุปสุดท้ายคือให้ผู้เล่นเข้าใจว่าเป้าหมายถัดไปคืออะไร เหตุใดคำสั่งจึงทำไม่ได้ และเพื่อนช่วยการเล่นอย่างไร จากนั้นให้การต่อสู้และโลก 3D ของ Xexoria เป็นเหตุผลที่ผู้เล่นอยากกลับมา ความถูกต้องระหว่างระบบต้องมาก่อนความกว้างของรายการฟีเจอร์
